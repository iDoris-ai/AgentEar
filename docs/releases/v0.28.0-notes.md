## v0.28.0 — Choosing Thai in Settings starts the model download; new installs open in English

**If you never open the language settings, recording, transcription, and conversation behave as in the previous release.**
An install that already saved an interface language keeps it. This release does not rewrite that setting to English.

### What this version does

A Thai colleague who lands on the English interface can recognize their own language in the Settings window and start the Thai recognition-model download from there.
Those two choices were already in the menu bar. The Settings window did not have them.

The top of the Settings window now has two rows:

- **Interface Language** (界面语言 / ภาษาของเมนู): English, 中文, ไทย. A new install, and any config with no `ui_lang` key, opens in English.
- **Recognition Language** (识别语言 / ภาษาที่ใช้ถอดความ): Auto (Chinese / English / Japanese / Korean / Cantonese), or Thai. When the Thai model is not installed, the row says the download is 574 MB and shows Download. During the download and the check, the row has no button. This downloader has no separate cancel, so there is no Cancel control.

Choosing **ไทย** under Interface Language does two things. The interface switches to Thai, and the app takes the same path as Recognition Language → Thai.
If the model is not installed yet, the download starts (about 574 MB, and it is not inside the app bundle). Until the download and the check finish, **the saved recognition language stays Auto**. During those minutes a recording must not call an engine that is not there yet.
The recognition row in the window stays on Thai, and the label shows the progress. After the model is installed, and only while Thai is still wanted, the saved recognition language becomes Thai.

Switching the interface back to English or 中文 leaves the recognition language as it is. To return to automatic recognition, choose it in the Recognition Language row.

The two rows remain two config fields, `ui_lang` and `asr_lang`. They are tied together only by the act of choosing ไทย.

### What an upgrade does

- A config that already has `ui_lang` (Chinese, Thai, or English) keeps that interface language.
- An older config with no such key opens in English.
- The Thai model is still downloaded on demand and is not in the app bundle. A model that is already on disk is not fetched again.
- Recognition that was already Auto stays Auto until someone chooses Thai in Settings or in the menu.

### Verification

On 2026-10-26, with the debug binary and `AGENTEAR_DATA` pointed at an empty temporary directory. `~/.agentear` and the running `/Applications/AgentEar.app` were left alone.

- The startup log showed `ui_lang: En` and `asr_lang: Auto`.
- The menu was English (Settings…, Interface Language, Recognition Language).
- The window title was AgentEar Settings. Interface Language was English, with the items English / 中文 / ไทย. Recognition Language was Auto (ZH / EN / JA / KO / Cantonese). The Thai row read “ไทย — download 574 MB”, and the button was Download.
- After choosing ไทย, the log recorded the interface-language change and “开始下载泰语模型（574 MB）”. `curl` fetched `ggml-distill-whisper-th-large-v3-q5_0.bin` from the `models-th-v1` release. The `.part` file grew from 0 to about 170 MB, and the window showed “กำลังดาวน์โหลด 31%”.
- The saved config was `ui_lang: th` and `asr_lang: auto`. The window title became “การตั้งค่า AgentEar”, and Interface Language stayed on ไทย.
- SIGTERM stopped that debug process and that `curl`.

The unit test `settings_start_in_english_and_keep_thai_selected_while_the_model_downloads` pins the behavior: the default is English, Thai recognition is requested only when the Thai interface is chosen, the popup stays on Thai while the model is downloading, and the retry button’s tag is not taken by the device menu.

### Limits

- The click used the debug binary from the repository, not the `.app` produced by `scripts/bundle.sh`. The packaged window was not clicked.
- The download was stopped at about 31%. The full 574 MB was not fetched, and the checksum and load smoke test were not run. This session showed that choosing Thai starts the download. The existing `on_thai_installed` path, which sets recognition to Thai after a successful install, was not reached.
- Switching from the Thai interface back to English or 中文 was not clicked. Those two options write `ui_lang` only.
- When the model is already installed, choosing ไทย sets recognition to Thai immediately. The temporary directory had no model, so that path was not clicked.

## 中文

## v0.28.0 —— 设置里选泰语就开始下载模型，新安装默认英语界面

**不打开语言设置的人：录音、转写、对话都和上一版一样。**
已经在配置里存过界面语言的安装保持原样，不会被改回英语。

### 这一版做了什么

泰语同事打开的是英语界面时，要能在设置窗口里认出自己的语言，并开始下载泰语识别模型。
菜单栏里这两项本来就有；设置窗口之前没有。

设置窗口最上面现在有两栏：

- **Interface Language / 界面语言 / ภาษาของเมนู**：English、中文、ไทย。新安装、配置里还没有 `ui_lang` 时，默认是 English。
- **Recognition Language / 识别语言 / ภาษาที่ใช้ถอดความ**：自动（中 / 英 / 日 / 韩 / 粤），或泰语。泰语模型没装好时，这一项写着要下载 574 MB，旁边有 Download。下载中和验证中不显示按钮（这个下载器没有单独的取消，假的 Cancel 不放）。

选界面语言里的 **ไทย** 会做两件事：界面改成泰语，并且走和「识别语言 → ไทย」同一条路。
模型还没装好就开始下载（约 574 MB，不进安装包）。下载和校验没完成之前，**配置里的识别语言保持自动**，不然这几分钟里每次录音都会因为引擎不在而失败。
窗口上的识别语言仍停在泰语那一项，进度写在标题里。装好并且当时还想要泰语，才把识别语言写成泰语。

把界面改回 English 或中文**不会**把识别语言改回去。要回到自动识别，在识别语言那一栏自己选。

这两栏在配置里仍是两个字段（`ui_lang` 和 `asr_lang`）。耦合只发生在「点了ไทย」这个动作上。

### 升级会发生什么

- 配置里已经有 `ui_lang`（中文、泰语或英语）的，升级后界面语言不变。
- 没有这个键的旧配置，按默认进入英语界面。
- 泰语模型仍是按需下载，不随包。已经下好的模型不会因为这次升级重下。
- 识别语言本来就是自动的，保持自动，直到有人在设置或菜单里选泰语。

### 验证

2026-10-26，调试二进制，`AGENTEAR_DATA` 指向空的临时目录（没有动 `~/.agentear`，也没有动正在运行的 `/Applications/AgentEar.app`）：

- 启动日志里的配置是 `ui_lang: En`、`asr_lang: Auto`。
- 菜单是英语（Settings…、Interface Language、Recognition Language）。
- 设置窗口标题是 AgentEar Settings。界面语言下拉当前是 English，三项为 English / 中文 / ไทย。识别语言是 Auto (ZH / EN / JA / KO / Cantonese)。泰语那一行是「ไทย — download 574 MB」，按钮是 Download。
- 在界面语言里点「ไทย」之后，日志出现「界面语言改为 ไทย」和「开始下载泰语模型（574 MB）」。`curl` 拉的是 `models-th-v1` 上的 `ggml-distill-whisper-th-large-v3-q5_0.bin`。`.part` 从 0 涨到约 170 MB，窗口显示「กำลังดาวน์โหลด 31%」。
- 落盘的配置是 `ui_lang: th`、`asr_lang: auto`。窗口标题变成「การตั้งค่า AgentEar」，界面语言停在 ไทย。
- 对这个调试进程发 SIGTERM 后，进程和这次 `curl` 都退出了。

单测 `settings_start_in_english_and_keep_thai_selected_while_the_model_downloads` 钉住：默认英语、只有选泰语界面才连带要泰语识别、下载中弹窗仍停在泰语、重试按钮的 tag 不会被设备菜单吃掉。

### 诚实边界

- 这次点击用的是仓库里的调试二进制，不是 `scripts/bundle.sh` 打出来的 .app。打包后的窗口没有再点一次。
- 下载在大约 31% 时停掉了，没有跑完 574 MB，也没有做校验和加载冒烟。所以「点了就开始下」是这次看到的；「下完并自动把识别语言改成泰语」仍是原有的 `on_thai_installed` 路径，这一轮没有跑到那一步。
- 从泰语界面点回 English / 中文没有再点一次。那两个选项的代码只写 `ui_lang`。
- 模型已经装好时，选「ไทย」会立刻把识别语言改成泰语。这一轮的临时目录里没有现成模型，这条没有点到。
