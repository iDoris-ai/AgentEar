## v0.29.3 — Double-tap conversation can use the Agent24 assistant; Qwen3 fallback is now visible

**If you do not connect AgentEar to Agent24, you will barely notice this release.** Signed with a Developer ID certificate and notarized by Apple.

### What this version does

- **Double-tap conversation can go through the Agent24 assistant (only when connected).** When AgentEar is attached to Agent24 and the host grants the assistant capability, a double-tap conversation turn now calls the Agent24 assistant interface instead of the plain chat path: the default model via iDoris, personal memory, and the agent loop when a knowledge base is on. AgentEar's own TTS still speaks the reply. If you are not attached, or the host does not support or has not granted the capability, behavior is unchanged. Tested end to end against a real agent24d (Agent24 main 8075f24f): 5/5 passed, one Chinese and one English turn each, and a "voice conversation" session appears in Agent24. (#148)
- **A fallback from Qwen3 is now visible.** When Qwen3-ASR fails and the turn falls back to SenseVoice (or Thai whisper), the menu bar title shows a warning mark; it clears after the next successful Qwen3 transcription. `--asr-bench` now marks a failed Qwen3 run as FAILED instead of recording SenseVoice's numbers under Qwen3's name, and the labels `*-cli` are renamed `*-oneshot`. Internally, the contract probe now checks only speech-server. (#150)
- **`agentear --timings` is clearer.** The heading states the `--last N` range, duplicate old-format dictation rows are removed, and the arithmetic in the per-turn timing log line now adds up. (#149)

### Verification

- `cargo test --locked` passes in CI on all merged PRs.
- Before publishing, the notarized package is smoke-tested with an isolated data directory: `--diagnose`, `--say`, `--transcribe`, `--ask`, `--talk-turn`, `--translate`. The release is only published if all of them pass.

### Limits

- Not tested: the agent loop path with a bound knowledge base, the prompt shown when the host replies `awaiting_approval`, and a real desktop double-tap with the microphone.
- The Agent24 path was verified against a development build of the host, not a released one.

## 中文

## v0.29.3 —— 双击对话可走 Agent24 助手；Qwen3 退回现在看得见

**不连接 Agent24 的用户基本无感。** 已用 Developer ID 证书签名并经 Apple 公证。

### 这一版做了什么

- **双击对话可以走 Agent24 助手（仅在已连接时）。** 当 AgentEar 已连接 Agent24、且宿主授予了助手能力时，双击对话的一轮改为调用 Agent24 的助手接口，而不是普通聊天路径：默认模型经 iDoris、带个人记忆，知识库开着时走 agent loop；回复仍由 AgentEar 自己的 TTS 念出。没连接 Agent24、或宿主不支持/未授予时，行为不变。已与真 agent24d（Agent24 main 8075f24f）端到端联调通过 5/5（中英各一轮，Agent24 里出现「语音对话」会话）。（#148）
- **Qwen3 退回现在看得见。** Qwen3-ASR 失败、这一轮退回 SenseVoice（或泰语 whisper）时，菜单栏标题会显示「⚠」，下一次 Qwen3 转写成功后熄灭。`--asr-bench` 在 Qwen3 失败时标 FAILED，不再把 SenseVoice 的数字记在 Qwen3 名下，标签 `*-cli` 改为 `*-oneshot`。内部：契约探针只查 speech-server。（#150）
- **`agentear --timings` 更清楚。** 标题写明 `--last N` 范围，旧格式的输入法行去重，每轮耗时日志里的算式现在能闭合。（#149）

### 验证

- 所有合并的 PR 都在 CI 里跑过 `cargo test --locked`。
- 发布前用公证后的新包在隔离数据目录里做冒烟测试：`--diagnose`、`--say`、`--transcribe`、`--ask`、`--talk-turn`、`--translate`，全部通过才会发布。

### 边界

- 未测：绑定知识库的 agent loop 路径、宿主返回 `awaiting_approval` 时的提示语、桌面上真实双击加麦克风。
- Agent24 这条路径是对宿主的开发版联调的，不是已发布版本。
