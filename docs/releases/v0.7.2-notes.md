## 这版改了什么

**按键手势**（jason 2026-09-14 定的）:

| 手势 | 结果 |
|---|---|
| **单击右 Command** | **输入法模式**——只说、只上屏,不出声(和以前一样) |
| **双击右 Command**(350ms 内两下) | **对话模式**——说完它用语音回答你 |
| 菜单栏 → 模式 | 两项都列出来带勾选,标题里显示当前在哪一档 |

手势是**每轮生效**的:这一轮怎么按,就按哪个模式走。组合键(Ctrl+Shift+R)没有双击这个维度,
它是显式的开始/停止,**不改模式**。

## 你看不到那个菜单,是因为标题只写了「模式」

这条是这版**专门修**的:上一版菜单里那一项叫「模式」,而你在找「对话模式」四个字,
不展开子菜单根本看不出有这一档。现在:

- 标题改成 **「模式: 对话」**(带当前模式,不展开也看得见)
- 触发键那一项的文案也改了:**「右 Command:单击 = 输入法,双击 = 对话」**——
  菜单里唯一能告诉你手势的地方就是这里

## 细节上踩到的两个坑(都写进了代码注释)

1. **「停止」不许改模式**。`finish()` 是在你松手那一刻读配置的;
   如果「停止」顺手切回输入法,双击选出来的对话模式会在松手瞬间被顶掉——
   症状看起来像「双击没生效」,其实是被自己停掉了。
2. **录音中收到双击只切模式、不停录音**。双击的第一次点击已经开了录音,
   第二次若按「再按一下停止」处理,会立刻停成 0.2 秒的碎片录音(会被当噪音丢弃)。
   双击的第二下因此被识别成「切模式」而不是「停止」。

顺带修掉一个真 bug:切模式时会话可能还不存在(启动时是输入法、中途双击切对话),
或存在但停在上轮的 `Idle`——那样状态机会**静默**拒掉后续转移(只写 warning),
统计变成自相矛盾的「0 轮」而声音照样出得来。现在切模式会把会话推到 `Listening`。

## 测试

`cargo test` **255 passed / 0 failed / 6 ignored**(v0.7.1 是 252);
clippy 8 条既有警告,**本版零新增**。

新增 4 条里最重要的一条是**手势真值表**(六种组合全钉住):真按键在单测里造不出来,
而「双击被写成两次单击」恰恰只能靠真按键暴露,所以把判据抽成纯函数测掉。
另外三条:停止不改模式、双击窗口边界含端点、时钟倒退不误判。

## ⚠️ 没做到的

**手势本身没有端到端测试**——`CGEventTap` 的回调跑不了单测,只有判据被覆盖了。
「真按两下会不会切过去」只有人肉能验,请你自己试一下。

AEC / VAD 自动打断 / 双讲 / 误打断率 / 端到端打断延迟 <300ms —— 仍全未测。
