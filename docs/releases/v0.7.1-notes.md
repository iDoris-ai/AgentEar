## 这版补上了什么

**对话模式的两个边车,现在由 AgentEar 自己负责拉起。**

上一版(v0.7.0)只会在日志里写一句「边车没起」——你点完菜单就去按键了,那条日志你看不到,
于是症状就是「按了键只有文字,没有声音」。这版改成 ADR-0002 §8 那条老规矩:
**连接优先、拉起兜底**。

切到对话模式(或启动时就是对话模式)之后:

1. 先探两个边车在不在;
2. 不在就按 `talk_llm_start_command` / `talk_tts_start_command` 拉起;
3. 等就绪(最长 90 秒),日志里逐步打出来。

全程在**后台线程**里做——90 秒的就绪等待放在主线程上,菜单栏会整整一分半不响应,
而那时候你正在按键。

### 默认不写死路径

两条拉起命令**默认是空的**,也就是「只连不拉」。理由和 M2 的 `llm_start_command` 一样:
**编译期路径不能写死**——那是开发机上的仓库路径,分发到别人机器上指向一个不存在的目录,
而且一旦被写进用户的 `config.json` 就固化了。**空的时候日志里会打出该跑哪条命令**,不静默。

想让它自己拉,把路径填上即可:

```json
{
  "talk_llm_start_command": ["/你的路径/AgentEar/scripts/serve-talk-llm.sh"],
  "talk_tts_start_command": ["/你的路径/AgentEar/scripts/serve-tts.sh"]
}
```

### 退出会收干净

**这是我们自己起的进程,退出就要收掉**——它们常驻约 4 GB(LLM 1.6 GB + TTS 2.5 GB),
留在后台你只能去活动监视器里找。

- 菜单 Quit → `talk::shutdown_spawned()`
- **`Ctrl+C` / `kill`(信号路径) → 信号处理函数里直接 `kill(2)`**。
  这条是这版特意补的:漏了它,信号退出会留下那两个进程。只做 `kill(2)`,
  符合 async-signal-safe(信号处理函数里不能锁 mutex、不能分配内存)。
- **只收我们自己拉起的**。你自己在终端里跑的服务,AgentEar 一律不动。

## 实测

不是单测,是真跑了一遍:

1. 杀掉两个边车 → 起 AgentEar(对话模式)→ 日志:
   `LLM 边车没起,按配置拉起…` → `等了 1.6s` → `已就绪`;`TTS…3.0s 已就绪` → `都就绪了`
2. `kill -TERM` AgentEar → **两个边车都随退出被收掉**(两个端口都不通了)

`cargo test` **252 passed / 0 failed / 6 ignored**(v0.7.0 是 248);clippy 8 条既有警告,
**本版零新增**。新增 4 条用例,其中一条把「边车动作」的四种组合全钉住——
最容易犯的错不是「拉不起来」,而是「autostart 开着但命令是空的」被当成已经处理过了。

## 已知没做

- **拉起失败后不重试**(只拉起一次,失败了要等下一次切模式或重启)。
- 菜单路径本身仍无自动化测试。
- **AEC / VAD 自动打断 / 双讲 / 误打断率 / 端到端打断延迟 <300ms 仍全未测**——
  这版和上版都只碰了边车生命周期,没碰音频图。
