## v0.26.1 —— 连接 Agent24 的凭证不再放钥匙串：升级不再弹「输入登录密码」

**独立使用 AgentEar（没点过「连接 Agent24」）的人：这一版什么都没变。**

### 修复（jason 2026-09-27 真机抓到）

v0.25.x 连上 Agent24 之后，**每次升级 AgentEar，第一次启动都会弹一个框**：
「AgentEar wants to access key "ai.idoris.agentear.agent24" in your keychain. To allow this, enter the
"login" keychain password.」

**原因**：连接凭证（附着 token）存在 macOS 钥匙串里。AgentEar 用的是**自签证书**（没有 Apple 开发者
Team ID），macOS 钥匙串的「分区列表」对这种 app 是按**这一次构建的哈希（cdhash）**认人的
（实测这个钥匙串项的分区里就是 `cdhash:4935334a…`）。每发一个新版本 cdhash 都变，macOS 就把新版本当成
「另一个程序」，于是再要一次密码。签名证书本身是固定的，这一层没问题；问题只在分区。

**修法**：凭证改存 **`~/.agentear/agent24/token`**（目录 0700、文件 0600，只有你自己能读写）。
- **为什么这样不降低安全性**：A3 附着协议的威胁模型本来就**不防同一用户下的其他进程**
  （Agent24 SPEC-ME3 §0；A3 设计 §11 Q2 也写了同 UID 下两种存法一样安全）——同一用户的程序
  本来就能以你的身份去调 `agent24` CLI。0600 文件与钥匙串在这个模型下等价，却不会每次升级都要密码。
- 写法照 ssh 私钥的规矩：临时文件以 0600 **创建**（不存在「先宽后改」的窗口）→ 写入 + fsync →
  rename → fsync 目录 → 写后再校验权限；**读时权限比 0600 宽就拒绝使用**（提示 `chmod 600` 或重新连接）；
  符号链接、非普通文件、属主不是你、空文件，一律不用。
- token 仍然**只在两处出现**：CLI 的输出（读完就写文件）与这个文件本身——不进 config.json、日志、
  命令行参数、事件。
- 不再依赖 `security-framework`（Cargo.lock 少了一串依赖）。

### 升级时会发生什么（从 v0.25.0–v0.25.2 升上来、已经连过 Agent24 的）

第一次启动时，AgentEar 发现「配对过但没有 token 文件」，就**自动代跑一次 `agent24 os attach add`
重新签发**一个新 token 写进文件，然后照常连接。**不弹任何框**。
- **绝不去读旧的钥匙串项**——读它就会弹框，那正是要修的问题。
- 旧钥匙串项里的 token 在重新签发那一刻就**作废**了（Agent24 那边同名注册 = 轮换）。
  AgentEar **也不去删它**（删它同样可能弹框）；它现在是一条没用的记录，想清掉可以打开「钥匙串访问」
  搜 `ai.idoris.agentear.agent24` 手动删。
- 这一步需要能跑 `agent24` CLI。实测：常驻的 agent24d 没在跑时，CLI 会临时拉起一个应答后收掉，
  **照样能签发**；等你打开 Agent24，AgentEar 用新 token 自动连上。
- 若 CLI 找不到或签发失败，设置里显示「需要重新配对」，点一下「连接 Agent24」即可。

### 新增两个诊断入口（和 `--talk-turn` 同类，不起守护进程）

- `agentear --agent24-pair`：跑一遍和设置里「连接 Agent24」**同一个**配对流程。
- `agentear --agent24-startup`：只跑一遍守护进程启动时的判定与迁移，打印启动计划、结果状态与
  token 文件状态（打码）。

### 验证

- 单元：token 文件 0600/目录 0700、原子替换不留临时文件、umask 0 下仍是 0600、宽权限（640/604/644/660）拒用、
  0400 照用、符号链接/空文件/目录拒用、`Debug` 不打出 token、启动计划真值表、`execute_plan` 调用点
  （迁移真的去签发、失败 → 需要重新配对、Connect/Unpaired/Repair 不代跑 CLI）、`creds_from` 判据。
  **7 处调用点变异全部变红**（权限检查关掉、创建时 0644、迁移当没配对、迁移不去签发、凭据接受宽权限、
  跟随符号链接、Debug 泄漏 token）。
- 真实链路（隔离 HOME 的 agent24d，Agent24 main `604e198`；隔离数据目录）：
  ① `--agent24-pair` → token 文件 600 / 目录 700，config 与日志里 grep 不到 token，`--talk-turn --host a3`
  握手成功（Qwen3-0.6B-4bit，tier Local）；② 删掉 token 文件模拟「钥匙串时代升级上来」→
  `--agent24-startup` 计划 `Reissue`，token_id 换新，新 token 握手成功，**旧 token 握手 auth_failed**；
  ③ 权限改 644 → 计划 `Repair`、状态「需要重新配对」；④ 杀掉 agent24d 后再迁移 → CLI 临时拉起 daemon，
  签发成功。
- `scripts/e2e-agent24.sh` 不依赖钥匙串（一直用 `--a3-token-file`），见 PR 描述里的重跑结果。

### 没做的

- 没有 Apple Team ID 签名。有了之后钥匙串会按 team 认人，回到钥匙串才有意义。
