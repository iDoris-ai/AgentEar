## v0.29.0 — Translated input, crash recovery for recordings, long one-shot Qwen3 transcripts

**If you change nothing, input-method mode behaves as before.** Translation is off by default. Crash recovery and the Qwen3 fix need no setup.

### What this version does

- **Translated input (new, off by default).** The menu bar has a new "Input output" submenu: Original / → English / → 中文 / → ไทย. With a target selected, what you dictate in input-method mode is translated before it is pasted. The menu-bar title shows a marker such as `→EN` while translation is on. You can also say "开启翻译" / "关闭翻译" / "翻译成英文", or "翻译成英文：…" to translate a single sentence without changing the setting. These voice commands are in the default command table only, so they appear for new installs; if you already have a `commands.json`, add them yourself.
  - Translation uses the local LLM sidecar at `talk_llm_url` (default `127.0.0.1:8794`, MiniCPM5-2B). If it is not running, times out (15 s), returns nothing, or returns the original, **the original text is pasted** and the reason goes to the log. The raw audio, transcripts, routes and knowledge base always keep the original text. Translations are stored separately in `derived/translations/`.
  - Your words stay on this machine only while `talk_llm_url` points to this machine. If you point it to a remote endpoint, each translation sends the transcript there.
  - → ไทย is not reliable: MiniCPM5-2B only declares English and Chinese.
  - Command line for testing: `agentear --translate "<text>" --to en|zh|th`.
- **A crash during recording no longer loses the whole recording.** The recording file is checkpointed to disk every 5 seconds. If the app is killed or crashes while recording, the next start repairs the file, stores it like a normal recording (marked `recovered` in `raw/manifest.jsonl`), and transcribes it in the background. The transcript is saved but not pasted. At most the last 5 seconds are lost.
- **Long Qwen3 recordings are no longer cut off with the resident switch off.** With Qwen3 selected and "Qwen3-ASR resident" off (the default), recordings longer than 60 seconds are now sent to a temporary copy of the patched `speech-server` (decode limit 6144 tokens), which is stopped right after. Shorter recordings use the command line as before. The per-request timeout now grows with the recording length.
- **`--diagnose` no longer hangs on the microphone.** The microphone probe gives up after 3 seconds and reports "microphone not responding (possibly waiting for permission or in use)", then continues with the other checks.
- **License notices corrected.** NOTICE now lists SenseVoiceSmall under the FunASR Model License v1.1 (not Apache-2.0) and adds whisper.cpp, speech-swift, MLX and the Thai model. Whether SenseVoiceSmall may be used commercially has not been confirmed with the licensor.

### What an upgrade does

Nothing is downloaded. The config gains `input_translate` only when you change it; a missing key means off.

### Verification

On 2026-11-11, with the new `.app` and an isolated data directory:

- `--diagnose` finished in 0.17 s and listed the input device (the v0.28.2 build hung on this machine).
- `--say` played synthesized speech.
- `--translate` with the local MiniCPM5-2B sidecar: 今天下午三点开会，讨论录音崩溃抢救的方案 → "Meeting at 3 pm today, discussing the solution for recovering from audio recording failures."; "Please review the pull request before lunch." → 请在午餐前审查拉取请求。
- `--ask` and `--talk-turn` (Chinese speech generated with macOS `say`) completed a full turn: heard 今天天气怎么样？ and spoke the answer.
- Crash recovery: a 5.6-second recording left in `raw/.tmp` with its header lengths zeroed (and a trailing half sample) was recovered at startup, its header repaired, recorded with `"recovered":true`, and transcribed word for word.
- In the PR #124 tests, a child process killed with `kill -9` while recording had its audio recovered after restart.
- In PR #126, a 241-second English recording made with `say` went from 348 words (cut off) to 604 words (complete).
- `scripts/lint-shell.sh`, `cargo test` (581 unit tests plus integration tests), and `cargo build --release` pass.
- Timings from this run are not quotable: the machine was under heavy load (swap nearly full).

### Limits

- Translated input and the "Input output" menu were not tested with real key presses or menu clicks.
- Translation quality was checked only on the two sentences above. Thai output was not evaluated.
- Translation runs on the same thread that reads the next key press, so it can delay the next recording by up to 15 s. Transcribing a recovered recording right after startup also holds that thread.
- Crash recovery was not tested with a real microphone and a real daemon killed mid-recording, or with a power loss.
- The long one-shot Qwen3 path was tested only with synthesized speech. It was not tested with a real long recording, the 15-minute option, or alongside the resident service.
- The `--diagnose` timeout path is covered only by unit tests; it was not observed on a truly stuck CoreAudio device.

## 中文

## v0.29.0 —— 翻译输入、录音崩溃抢救、Qwen3 一次性长录音不再截断

**什么都不改，输入法模式和以前一样。** 翻译默认关。崩溃抢救和 Qwen3 修复不用设置。

### 这一版做了什么

- **翻译输入（新功能，默认关）。** 菜单栏新增「输入法输出」子菜单：原文 / → English / → 中文 / → ไทย。选了目标语言后，输入法模式下说的话先翻译再上屏。翻译开着时菜单栏标题显示 `→EN` 之类的标记。也可以说「开启翻译」「关闭翻译」「翻译成英文」，或者「翻译成英文：……」只翻这一句、不改设置。这些语音指令只在默认指令表里，所以新安装才有；已经有 `commands.json` 的用户要自己加。
  - 翻译走 `talk_llm_url` 的本机 LLM 边车（默认 `127.0.0.1:8794`，MiniCPM5-2B）。边车没起、超时（15 秒）、返回空或原样返回时，**原文照样上屏**，原因写进日志。原始音频、转写、routes、知识库永远存原文，译文另存在 `derived/translations/`。
  - 只有 `talk_llm_url` 指向本机时，说的话才不出这台机器。指向远端时，每次翻译都会把转写发给那个远端。
  - → ไทย 不稳：MiniCPM5-2B 只声明支持中英文。
  - 测试用命令行：`agentear --translate "<文字>" --to en|zh|th`。
- **录音中途崩溃不再丢整段。** 录音文件每 5 秒落一次盘。录音时程序被杀或崩溃，下次启动会修好文件、按正常录音存下（`raw/manifest.jsonl` 里标 `recovered`），并在后台转写。转写会存下来，但不上屏。最多丢最后 5 秒。
- **Qwen3 常驻开关关着时，长录音也不再截断。** 选了 Qwen3 且「Qwen3-ASR 常驻」关着（默认）时，超过 60 秒的录音改为临时拉起补丁版 `speech-server`（解码上限 6144 个 token），转完立刻停。短录音照旧走命令行。单次请求的超时按录音时长放宽。
- **`--diagnose` 不再卡在麦克风上。** 麦克风探测 3 秒没反应就报「麦克风无响应（可能等待授权或设备被占用）」，然后继续其余自检。
- **许可证声明更正。** NOTICE 把 SenseVoiceSmall 改为 FunASR Model License v1.1（不是 Apache-2.0），并补上 whisper.cpp、speech-swift、MLX 和泰语模型。SenseVoiceSmall 能否商用还没向许可方确认。

### 升级会发生什么

不下载任何东西。只有改过设置，配置里才会出现 `input_translate`；没有这个键就等于关。

### 验证

2026-11-11 用新 `.app`、隔离的数据目录：

- `--diagnose` 0.17 秒跑完，列出了输入设备（v0.28.2 的包在这台机器上会卡住）。
- `--say` 播出了合成语音。
- `--translate` 接本机 MiniCPM5-2B 边车：「今天下午三点开会，讨论录音崩溃抢救的方案」→ "Meeting at 3 pm today, discussing the solution for recovering from audio recording failures."；"Please review the pull request before lunch." →「请在午餐前审查拉取请求。」
- `--ask` 和 `--talk-turn`（用 macOS `say` 合成的中文语音）走完一整轮：听到「今天天气怎么样？」并念出了回答。
- 崩溃抢救：在 `raw/.tmp` 里放一段文件头长度被清零、末尾多半个采样的 5.6 秒录音，启动时被抢救，文件头修好，清单记为 `"recovered":true`，转写一字不差。
- PR #124 的测试里，录音中途被 `kill -9` 的子进程，重启后录音找回。
- PR #126 里，一段用 `say` 合成的 241 秒英文录音，从 348 词（被截断）变成 604 词（完整）。
- `scripts/lint-shell.sh`、`cargo test`（581 条单测加集成测试）、`cargo build --release` 通过。
- 这一轮的耗时数字不能引用：机器负载很高（swap 几乎用满）。

### 边界

- 翻译输入和「输入法输出」菜单没有用真实按键和真实菜单点击测过。
- 翻译质量只看了上面两句，泰语输出没有评估。
- 翻译和读取下一次按键在同一个线程上，最多会让下一次录音晚 15 秒开始。启动后马上转写抢救录音时，也会占着这个线程。
- 崩溃抢救没有用真实麦克风加真守护进程录到一半被杀的场景测过，也没测断电。
- Qwen3 一次性长录音只用合成语音测过，没测真实长录音、15 分钟档，也没测和常驻服务同时用的情况。
- `--diagnose` 的超时分支只有单测覆盖，没在真卡死的 CoreAudio 设备上观察到。
