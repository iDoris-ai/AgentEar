## 这版加了什么

**两种模式,默认输入法。切换入口在菜单栏 → 模式。**

| 模式 | 按一下录音键 → | 默认 |
|---|---|---|
| **输入法模式** | 录音 → 转写 → 剪贴板 / 上屏。**不出声** | ✅ **是** |
| **对话模式** | 上面全部 + 大模型回答 → 语音念出来（按录音键可打断它） | 否 |

点一下立刻生效,不用重启。这一版之前,通话只能手改 `config.json` 里的 `talk_enabled`——
**对用户等于没有入口**,这就是 v0.6.0 的问题。

## 几个刻意的设计选择

- **两个模式都列出来带勾选**,没做成一个「对话模式」单开关。单开关的失败形态是
  **用户不知道自己现在不在哪个模式里**。
- **默认输入法**:对话模式要两个边车进程,没起的时候会让每次录音白等一次超时。
  输入法模式就是 M1 以来那条路,零外部依赖。
- **两种模式前半段完全相同**(录音/落盘/转写/上屏),只有后半段要不要出声不同。
  所以**走错模式只会让这一轮没声音,不会丢转写**。
- **切回输入法时会掐掉正在播的回答**;切进对话模式会**先探两个边车**并把「谁没起」写进日志——
  那两个进程跑在别处,光看菜单看不出来。

## 升级注意

v0.6.0 的 `talk_enabled: true`(如果你手改过)**会自动迁移成对话模式**,所以那台机器升级后
**仍然是对话模式**,不会悄悄变安静。迁移只做一次,之后配置文件里 `talk_enabled` 自动消失。

迁移的判据是**「新键根本没出现过」而不是「新键等于默认值」**——否则你从菜单切回输入法之后,
下次启动会被旧字段顶回对话模式(菜单显示输入法、行为却是对话,属于最难查的一类 bug)。

## 怎么用

```bash
scripts/setup-talk.sh        # 只用对话模式才需要:下两个模型(约 3.5 GB,不随包分发)
scripts/serve-talk-llm.sh    # 对话模式的 LLM 边车 → 127.0.0.1:8794
scripts/serve-tts.sh         # 对话模式的 TTS 边车 → 127.0.0.1:8765
```

菜单栏图标 → **模式** → 选「对话模式」,然后按录音键说一句即可。
`./target/release/agentear --diagnose` 会打出当前模式和两个边车在不在。

## 测试

`cargo test` **248 passed / 0 failed / 6 ignored**;clippy 8 条既有警告(本版新增代码零警告)。

新增 9 条用例,其中 4 条钉的是**「点菜单真的切对模式」**:菜单本身跑在 AppKit 主线程上点不了,
但最容易出的错恰恰是 **tag 和模式的对应关系写反**(点「输入法」却切到「对话」)——
那种错误看菜单是发现不了的(两项都在、勾选也对,就是行为反了)。
所以把 tag↔模式 的映射抽成纯函数并测掉。

## ⚠️ 没做 / 没变

- **AEC、VAD 自动打断、双讲、误打断率、端到端打断延迟 <300ms 仍然全未测**——
  和 v0.6.0 一样,这版只加了入口,没有碰音频图。
- **仍然没有「起/停一次通话」的入口**:模式是**持久设置**,不是一次会话的开始与结束。
- **菜单路径没有端到端测试**(AppKit 那套点不了),点了之后的三个副作用
  (写配置 / 掐播放 / 探边车)是代码审查 + 日志确认的。
- 泰语在大模型侧仍不稳定;4bit 与 bf16 质量对比仍未做;天气那句仍是**本地写死场景**。
