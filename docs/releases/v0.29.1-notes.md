## v0.29.1 — Qwen3 upgrade recovery fix, safer Agent24 confirmations

**If you do not use Qwen3 and do not connect Agent24, nothing changes for you.** This release is signed with a Developer ID certificate and notarized by Apple (v0.29.0 was published with a local self-signed certificate by mistake; this one opens without a Gatekeeper warning).

### What this version does

- **Qwen3 upgrade no longer gets stuck on SenseVoice.** When an upgrade replaces the Qwen3 runtime, the app falls back to the bundled SenseVoice while it downloads the new runtime (about 99 MB). Before, if the app quit between "runtime installed" and "switch back to Qwen3 saved", the recovery marker was already gone and the app stayed on SenseVoice for good. Now the marker is cleared only after the switch-back is saved, and a start that finds the runtime installed with the marker still present switches back without downloading again. (FU-21, #131)
- **Connected to Agent24: confirmations stay honest.** If the connection drops and reconnects while a confirmation is pending, AgentEar no longer sends the old confirmation to the new host. A pending confirmation that expires is now rejected at the host right away, instead of when you next speak or press the key. If your confirm or cancel could not be delivered, the console now says so instead of printing "confirmed". (FU-27/28, #140)
- **Proposal loop with Agent24 (T6.1.3).** When attached, AgentEar sends proposals and executes nothing itself; a rejected proposal is never executed locally. (#129)

### Not user-visible, also in this release

- Mac App Store prototype behind a build option (`app-store` feature): bundle id `ai.idoris.agentear.mas`, separate build number, sandbox probe kept out of submission builds. It is not published and cannot be uploaded yet (no Apple Distribution certificate, and the bundled SenseVoice license needs a commercial answer first). Research on commercially usable replacements is in `docs/asr-commercial-alternatives.md`.
- Packaging script: dry-run mode with behavior tests, refuses a symlinked `vendor/`, copies the binary cargo actually built.
- Pinned upstreams: rebuild script for the bundled ASR binaries, per-file sha256 lists for MiniCPM5 and VoxCPM2 weights, pip constraints. A merge queue now guards `main`.

### Verification

- `cargo test --locked` passes in CI on every merged PR.
- Before publishing, the notarized package is smoke-tested with an isolated data directory: `--diagnose`, `--say`, `--transcribe`, `--ask`, `--talk-turn`, `--translate`. The release is only published if all of them pass.

### Limits

- Agent24 confirmation fixes were tested only against the built-in fake host, not a real `agent24d`.
- The Qwen3 recovery fix was tested with unit tests (decision table), not by killing a real upgrade halfway.
- Translated input, crash recovery and the new menu from v0.29.0 still have no real-key / real-menu acceptance run.

## 中文

## v0.29.1 —— 修 Qwen3 升级后卡在 SenseVoice，附着 Agent24 时的确认更可靠

**不用 Qwen3、也不连 Agent24 的话，你这边没有变化。** 这一版用 Developer ID 证书签名并经 Apple 公证（v0.29.0 误用本机自签证书发布，打开会被 Gatekeeper 拦；这一版不会）。

### 这一版做了什么

- **Qwen3 升级后不再永远停在 SenseVoice。** 升级换了 Qwen3 运行时之后，应用先退回随包的 SenseVoice，同时后台下载新运行时（约 99 MB）。以前如果在「运行时装好」和「切回 Qwen3 的配置写入」之间退出，恢复标记已经被清掉，应用就一直停在 SenseVoice。现在标记在切回写入成功之后才清；启动时发现运行时已装好、标记还在，会直接切回，不再重复下载。（FU-21，#131）
- **连着 Agent24 时，确认更老实。** 待确认期间连接断开又重连，AgentEar 不再把旧的确认发给新宿主。待确认超时后，会立刻告诉宿主「拒绝」，不用等你下一次开口或按键。你的确认 / 取消没送到宿主时，控制台会如实说明，不再打印「已确认」。（FU-27/28，#140）
- **和 Agent24 的提案闭环（T6.1.3）。** 附着时 AgentEar 只发提案、自己不执行；被拒绝的提案本地零执行。（#129）

### 同一版里，但你看不到的

- Mac App Store 原型（编译开关 `app-store`）：bundle id `ai.idoris.agentear.mas`，构建号与版本号分开，沙箱探针不进提审构建。**还没有发布，也还不能上传**（缺 Apple Distribution 证书；随包 SenseVoice 的商用许可也要先有答复）。可商用替代模型的调研在 `docs/asr-commercial-alternatives.md`。
- 打包脚本：干跑模式 + 行为测试；`vendor/` 是符号链接时拒绝打包；拷贝 cargo 实际编出来的二进制。
- 锁定上游：随包 ASR 二进制的复建脚本、MiniCPM5 / VoxCPM2 权重逐文件 sha256、pip 版本约束。`main` 现在由 merge queue 把关。

### 验证

- 每个合并的 PR 都在 CI 里跑过 `cargo test --locked`。
- 发布前用公证后的新包在隔离数据目录里做冒烟测试：`--diagnose`、`--say`、`--transcribe`、`--ask`、`--talk-turn`、`--translate`，全部通过才会发布。

### 边界

- Agent24 确认修复只在内置的假宿主上测过，没有连真实的 `agent24d`。
- Qwen3 恢复修复只有单测（判定真值表），没有真的在升级中途杀进程验证。
- v0.29.0 的翻译输入、崩溃抢救和新菜单，仍然没有做真实按键 / 真实点击的验收。
