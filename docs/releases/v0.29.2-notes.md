## v0.29.2 — Qwen3 no longer stalls for two minutes, and every dictation turn is now timed

**If you use the bundled SenseVoice (the default), the only visible change is the new timing log.** If you chose Qwen3-ASR, this release fixes a stall that could make one transcription take two minutes or more. Signed with a Developer ID certificate and notarized by Apple.

### What this version does

- **Qwen3-ASR no longer asks Hugging Face before loading a model.** The upstream loading library contacted the Hugging Face Hub on every model load before looking at the local files. AgentEar runs Qwen3 in a sandbox that blocks outgoing connections, and the library did not treat that block as "offline": it retried five times (about two minutes) and failed, then the one-shot fallback hit the same wall. The models are installed at a pinned revision with per-file checksums, so no update check is needed. The runtime now loads a complete local copy without any network request, and reports a missing file immediately instead of retrying. Measured on a real 0.6B install inside the same sandbox: 3.0 s for the first transcription including model load, 0.08 s for the next; before, about 118 s then failure. (FU-31, #145)
- **One-shot Qwen3 transcription uses the patched server for every recording length** (before, only recordings over 60 s), and **if Qwen3 fails, that turn falls back to SenseVoice** so words are not lost. Pinning the engine with `--asr-backend` disables the fallback.
- **The Qwen3 runtime is replaced** (`speech-runtime-v0.0.28-agentear.3`, about 99 MB). After upgrading, the app downloads it in the background and switches back to Qwen3 when it is ready; until then it uses SenseVoice.
- **Every dictation turn is timed (new).** For each input-method turn the app records how long each step took (save, transcription split into process start and decoding, term correction, labelling, writing the knowledge base, paste) and what the machine was doing (load, swap use, memory pressure). Numbers and enums only; no transcript text is stored. One line per turn goes to the log, and `agentear --timings` has a new "input-method" section that lists the slow turns, which step dominated, and compares them by machine load and swap use. It answers "is it AgentEar or is the machine busy". (FU-32, #146)

### Verification

- `cargo test --locked` passes in CI on both merged PRs.
- Before publishing, the notarized package is smoke-tested with an isolated data directory: `--diagnose`, `--say`, `--transcribe`, `--ask`, `--talk-turn`, `--translate`. The release is only published if all of them pass.

### Limits

- The Qwen3 fix was verified on the command line against a real model in the sandbox, not inside the installed app. The 1.7B model, the Thai path, the background runtime download on upgrade, and the fallback to SenseVoice end to end have not been tested.
- The timing log has only been tested with synthetic data and unit tests; the first real dictation turns will show whether the "other" column (time not attributed to any step) is small.
- Transcription can still be slow when the machine is out of memory; this release makes that visible, it does not remove it.

## 中文

## v0.29.2 —— Qwen3 不再卡两分钟，每一轮听写都有分段耗时

**用默认的随包 SenseVoice 的话，你唯一能看到的变化是新增的耗时日志。** 如果你选了 Qwen3-ASR，这一版修掉了一个会让单次转写卡两分钟以上的问题。已用 Developer ID 证书签名并经 Apple 公证。

### 这一版做了什么

- **Qwen3-ASR 加载模型前不再先问 Hugging Face。** 上游的加载库每次加载模型都先联网问一次 Hub，然后才看本地文件。AgentEar 把 Qwen3 放在禁止联网的沙箱里跑，库把这个拦截当成「下载失败」而不是「离线」：重试 5 次（约两分钟）后报错，一次性转写的退路又撞同一堵墙。我们的模型是按钉死的版本安装的、有逐文件校验，不需要更新检查。现在运行时在本地文件完整时直接加载，不发任何网络请求，缺文件立刻报错而不是重试。在同样的沙箱里用真实的 0.6B 实测：首次转写（含加载）3.0 秒，之后 0.08 秒；以前是约 118 秒后失败。（FU-31，#145）
- **一次性 Qwen3 转写不论录音多长都走补丁版服务**（以前只有超过 60 秒的才走），**Qwen3 失败时这一轮退回 SenseVoice**，不丢字。用 `--asr-backend` 锁定引擎时不退回。
- **Qwen3 运行时更换**（`speech-runtime-v0.0.28-agentear.3`，约 99 MB）。升级后应用在后台下载，装好自动切回 Qwen3；这期间先用 SenseVoice。
- **每一轮听写都计时（新增）。** 输入法模式每一轮记录各环节用了多久（保存、转写拆成进程拉起和解码、术语纠错、标签识别、写知识库、上屏），以及当时机器的状态（负载、swap 用量、内存压力）。只存数字和枚举，不存转写文字。每轮在日志里一行汇总，`agentear --timings` 多出「输入法模式」一节，列出慢的轮次、哪个环节占大头，并按机器负载和 swap 用量分组对比。它回答的是「慢是 AgentEar 的问题，还是机器太忙」。（FU-32，#146）

### 验证

- 两个合并的 PR 都在 CI 里跑过 `cargo test --locked`。
- 发布前用公证后的新包在隔离数据目录里做冒烟测试：`--diagnose`、`--say`、`--transcribe`、`--ask`、`--talk-turn`、`--translate`，全部通过才会发布。

### 边界

- Qwen3 修复只在命令行里用真实模型、在沙箱里验证过，没有在装好的应用里跑过。1.7B、泰语路径、升级时后台下载新运行时、退回 SenseVoice 的端到端流程都还没测。
- 耗时日志只用合成数据和单测验证过；第一批真实听写会告诉我们「其他」一栏（没有归到任何环节的时间）是否足够小。
- 机器内存耗尽时转写仍然可能很慢：这一版让它可见，没有让它消失。
