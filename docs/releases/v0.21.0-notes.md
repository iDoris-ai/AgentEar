## v0.21.0 —— 录音开始 / 结束提示音

jason 2026-09-26 要的：按一下右 Command，得**听得见**话筒开了；停下来，
要一个**不一样的**声音表示「结束了、开始转文字」；双击也一样。
这样按完键不用盯着菜单栏，就知道它确实在跑。

### 听到什么

| | 输入法模式（单击） | 对话模式（双击） |
|---|---|---|
| 开始录音 | 嘟（高） | 嘟、嘟（高） |
| 结束录音 | 嘟（低） | 嘟、嘟（低） |

- 高音 1320 Hz、低音低一个八度（660 Hz）——不用学就分得出「开」和「关」。
  每个音 70ms，两声之间隔 60ms。
- **双击**：第一下按下去时还不知道会不会有第二下，所以先响一声；
  第二下到了再**补一声**，你听到的就是跟着手指节奏的「嘟、嘟」，不会变成三声。
- **开始音只在麦克风真的打开之后才响**。开麦失败就不响——
  **没听到开始音 = 没在录**，这正是这个提示音要告诉你的事。
- **结束音在麦克风关掉之后才响**，不会被录进这一段的结尾。
  录音太短被丢弃、短按确认、超过 300 秒自动停止，也都会响结束音。
- 播放回答时按键打断：先掐掉回答，再响开始音。
- **设置窗口 → 「录音提示音」**可以关掉，**默认开**（旧配置里没有这个键也算开）。
  打开时会当场响一声。

### 数字（都是实测，边界写在下面）

- **跟手**：播放线程收到 → `play()` 返回，预热后 **8.8–27.6ms（n=20）**；
  闲置 20 秒后约 **48ms**（n=3）。进程里第一次播要 97–142ms，
  所以守护进程启动时先静音地播一次，把这笔开销提前付掉。
  ⚠️ 这是「交给系统」的时间，**不是扬声器真的出声**的时间，后者没测。
- **不会把转写带偏**：用 `scripts/cue-asr-check.py` 把守护进程播的**同一段波形**
  混进中 / 英 / 泰三段语音（开始音、双击两声、对话两声、结尾漏进的结束音），
  12 种组合每种跑 3 次，**转写与不加提示音时逐字相同**。
  只有提示音、没人说话时，中英（SenseVoice）转出的是**空**。
  原始结果：`docs/data/cue-asr-2026-09/`。
- `cargo test` **309 passed / 0 failed / 7 ignored**（+8 条：提示音真值表 12 格、
  双击只响两声、开始与结束音高不同、波形时长、淡入淡出、WAV 头、名字往返、配置默认开）。

### 没验证到的（请手测）

- ⚠️ 上面「不带偏转写」是**数字混音**，不是扬声器 → 空气 → 麦克风的真实路径
  （开发环境的麦克风被系统权限静默了，录到的全是 0）。
- **蓝牙耳机**的输出延迟可能有一两百毫秒，开始音可能明显晚于麦克风打开——没测。
- **真实按键 + 人耳**没测。建议这样过一遍：
  1. 单击右 Command，听到一声高音，说一句，再单击，听到一声低音；
  2. 双击右 Command，听到两声高音，说一句，单击停，听到两声低音；
  3. 对话模式下让它念一段长回答，播放中按键：回答立刻停、响开始音；
  4. 设置里关掉「录音提示音」，重复 1，应当完全不响。

### 顺带发现的既有问题（不是这版引入的）

- **泰语模式下「只按键不说话」会上屏幻觉文字**：whisper 在纯静音上本身就会转出
  `The` 之类（对照组，没有提示音），混了提示音只是换成 `ค่ะ` / `and the`。
  这是 whisper 的静音幻觉，跟提示音无关，已记账，单独处理。
