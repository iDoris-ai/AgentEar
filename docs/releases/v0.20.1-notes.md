## v0.20.1 —— 崩溃后自动拉起

jason 2026-09-26 拍板：录音中途进程崩溃，**丢掉当前那一段可以接受，但要能自动恢复、继续用**。

### 改了什么

- **开机自启的 plist**（`~/Library/LaunchAgents/ai.idoris.agentear.plist`）从
  `KeepAlive = false`（崩了就一直不在）改为
  `KeepAlive = { SuccessfulExit = false }`：**异常退出才拉起**，正常退出不拉。
- **SIGTERM 现在以退出码 0 结束**（收拾完边车之后）。不这么改的话，
  「被信号杀死」在 launchd 眼里不算正常退出——你在终端 `kill` 它想停掉，
  launchd 10 秒后又会把它拉回来。菜单「退出」本来就是正常退出。

### 实测（临时 launchd job + shell 替身，测完已卸载）

| 退出方式 | 会被拉起吗 |
|---|---|
| `kill -9` | ✅ 拉起 |
| `exit 1` | ✅ 拉起 |
| 未捕获的信号致死 | ✅ 拉起（所以 SIGTERM 必须改成 exit 0） |
| `exit 0` / 捕获 SIGTERM 后 `exit 0` | ❌ 不拉起 |

拉起受 launchd 默认 10 秒节流（按上次启动时间算）。生成的 plist 过 `plutil -lint`
（有测试钉住）。**菜单 Quit 的退出码没在真 app 上实测**——按 Apple 文档
`NSApplication terminate` 调的是 `exit(0)`。

### ⚠️ 边界

- **只对登录时由 launchd 拉起的那个实例生效。** 从 Finder / 启动台双击打开的实例
  不归 launchd 管，崩了不会被拉起。
- **升级后要再登录一次才生效**：新版第一次启动会把 plist 改写成新内容，
  但按 v0.20.0 的规矩只写文件、不调 launchctl，所以当前登录会话里 launchd 手上
  还是旧定义。
- **崩溃那一刻正在录的那段仍然会丢**（还在内存里，没落盘）。这是拍板时接受的代价，
  不是修掉了。
- 启动阶段的永久性错误（比如数据目录打不开）会变成**每 10 秒重启一次**，
  菜单栏图标会反复出现；原因看 `~/.agentear/agentear.log`。
- 开机自启关着（设置里关掉）的用户：没有 plist，也就没有自动拉起。
- **没有单实例保护**（这一版之前就没有）：如果 launchd 那个实例崩了，
  你在它被拉起前的 10 秒里又手动打开了一次，就会同时跑两个，抢同一个热键。
  概率低，但自动拉起让这个窗口第一次存在，记在这里。
