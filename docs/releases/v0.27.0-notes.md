## v0.27.0 —— Qwen3-ASR 常驻服务改用我们自己编译的运行时（T3.5.9 方案 B-lite）

**没选 Qwen3-ASR 的人：这一版什么都没变。**

### 这一版做了什么

v0.26.2 修的是「超过 4 GiB 就重启」——从外面兜底，没碰根因。这一版动了根因：

speech-server（speech-swift v0.0.28）的 Qwen3-ASR 转写路径每次请求后不释放 MLX 用过的
Metal 缓冲区，0.6B（默认档）又没有上游给 1.7B 准备的那层缓存上限保护。结果是常驻服务
越用越涨（v0.26.2 的发布说明记过：实测 25 段真实录音后到 47–49 GB）。

现在 AgentEar 不再直接用上游发布的 `speech-server`，改成**自己从上游同一份 pinned 源码
+ 一个小补丁编译**（补丁见 [`patches/speech-swift-v0.0.28-agentear.patch`](../../patches/speech-swift-v0.0.28-agentear.patch)，
构建脚本见 [`scripts/build-speech-runtime.sh`](../../scripts/build-speech-runtime.sh)）：
**只换 `speech-server` 这一个二进制**，`speech` CLI、`mlx.metallib`、各个语音包 bundle
仍是官方发布包里原样那份（不需要装 Metal Toolchain 自己编 `.metallib`）。

补丁本身很小：加一个默认不生效的环境变量开关（`AGENTEAR_MLX_CACHE_MB`）——设了才会给
MLX 设缓存上限、每次请求后清缓存；不设时这个二进制与官方版本行为完全一致。AgentEar
自己起 speech-server 时会传 `256`（取值依据与 TTS 边车 v0.17.0 一致）。

实测（25 段真实录音 ×3 轮，`docs/data/qwen3-memory-2026-10/README.md`）：补丁版末态
**≈ 865 MB**、请求中峰值 **2.36–2.43 GB**；不开补丁与官方二进制一致，涨到 **47–50 GB**。
速度未检出差异，转写文字 25/25 逐字相同——这个补丁只改内存生命周期，不改转写结果。

发布前又拿**正式打包、自己发布、自己下载**的这份运行时跑了一遍同一批 25 段录音
（`--asr-bench ... --runs 25 --only qwen3-0.6b-resident`）：`server_footprint_mb`
全程在 998–1357 MB，**零次「超过上限」重启**。

**v0.26.2 的「超过 4 GiB 就重启」没有删**，当成最后一道保险留着：它不依赖我们的运行时
来源对不对，单次超长录音的峰值它也还是唯一能兜住的那道闸。

### 升级会发生什么

已经装过 Qwen3-ASR 的人升级后：模型权重不会重新下（判据与运行时版本号无关），但运行时
版本号变了，旧的 `speech-v0.0.28/` 目录对不上，会在**后台静默补下约 99 MB 的新运行时**
（不是模型，是运行 Qwen3-ASR 的那个可执行文件 + 相关文件）。下完之前这一轮启动先退回
随包的 SenseVoice（日志会写清楚原因，不是静默降级），补完之后下一轮自动换回 Qwen3-ASR,
不需要去设置里重新选一次。如果升级期间自己在设置里手动切了别的识别引擎，这次自动换回
不会把它顶回去。

旧版本号对应的运行时目录（`~/.agentear/models/qwen3/runtime/speech-v0.0.28/`）**不会被
自动删**——删错一个我们不完全确定内容的目录，代价比它省下的那点磁盘（约 370 MB）大，
想清理的话自己删就行。

### 诚实边界

- **只有 0.6B（默认档）做过这一轮的内存实测**。1.7B 本身已经有上游那层缓存上限保护
  （`min(4 GB, 物理内存 1/4)`），这一版的补丁对它的影响没有专门验证过。
- **`mlx.metallib` 仍是上游官方发布包里原样那份**——我们没装 Metal Toolchain，没法自己编
  `.metallib`；这个文件只跟上游版本绑定，不跟这次的补丁绑定。
- 这个补丁改的是内存生命周期，**不是转写质量**；常驻形态的准确率仍然没有用 60×3 组语料
  重新评过，见 T3.5.9 已有的诚实边界。
- 补丁的来源链是本仓库自己维护的（`patches/` + `scripts/build-speech-runtime.sh`），
  没有走上游 PR 合并那条路——上游要是发了修好的官方版本，再评估是否切回去、删掉这条自建链路。

### 开发者

- `src/qwen3.rs` 的 `SPEECH_VERSION` 从 `v0.0.28` 改成 `v0.0.28-agentear.1`：换补丁 /
  换上游版本都走同一套流程——改补丁或重编脚本 → 跑 `scripts/build-speech-runtime.sh` →
  发一个新的 `speech-runtime-<版本>` GitHub release → 把新的 sha256 / 字节数填进常量。
- `RUNTIME_URL` 现在指向 `iDoris-ai/AgentEar` 自己的 release，不再指向
  `soniqo/speech-swift` 的 release。
