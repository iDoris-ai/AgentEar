## v0.23.1 —— 修 v0.23.0 评审遗留：命令行不再杀掉守护进程的常驻识别服务

**只影响开了「Qwen3-ASR 常驻」的人**，而且只在你一边开着 AgentEar、一边在终端跑
`agentear --transcribe` / `--talk-turn` / `--asr-bench` 这类命令时才会碰到。
日常按键说话不受影响。

### 修了什么

- **守护进程和命令行不再互相杀对方的常驻服务**（PR #93 评审 N1）。
  v0.23.0 里两边共用一个 `speech-server.pid`：命令行会把守护进程正在用的常驻服务
  当成「上次没收干净的孤儿」收掉，还会把记录改写成自己的；结果是守护进程下一句话
  要重新冷启动一次（1–2.5 GB，多等一两秒，**不丢字**），而且它的孤儿兜底记录也没了。
  现在每个拉起服务的 AgentEar 进程各记各的（`speech-server-<进程号>.pid`），
  **拉起它的那个进程还活着，别人就不碰**；只有拉起者已经不在了，才当孤儿收掉，
  动手前照旧核对命令行，确认是我们自己的 speech-server。
- **文档如实写沙箱的边界**：speech 跑在「禁止出站 TCP」的沙箱里，挡的是
  **静默联网下载模型**；UDP 和文件系统并没有禁，所以它**不是隐私边界**。
  原来模块注释里「不会把录音相关的任何东西送出去」是夸大，已改正。
- **`--asr-bench` 出错时也把配置恢复回去**（原来会停在最后测的那一档）。
- 菜单里「音色」最多列 100 条，避免和识别引擎 / 下载按钮的菜单编号撞车
  （实际不会有这么多音色，属防御性修复）。

### 验证

- 新增测试用真进程复现评审场景：另一个「还活着的 AgentEar」拥有的常驻服务，
  命令行视角去收，**不会被杀**；拥有者退出后才被当孤儿收掉。
  在调用点做了三处变异（绕过拥有者判断 / 绕过命令行核对 / 判据恒为收），测试都会变红。
- `--asr-bench` 出错后的配置：修前停在 `builtin / 0.6b / 不常驻`，修后恢复为原值。
- 测试不启动守护进程、不碰真实数据目录。
