# v0.22.0 —— 语音服务端口被占时自动换端口；服务起不来时用 `say` 念一句

**起因**：2026-09-26 jason 的机器上，TTS 默认端口 **8765** 被一个桌面 app 占着（对 `/health` 回 HTTP 401），
对话模式那一轮整轮没声音。v0.21.1 修到了「报清楚是谁占的、不再误拉起」，
jason 接着拍板三条（2026-09-26）：**换掉默认端口 / 被占了自动换端口拉起 / 起不来时用 say 提示**。这一版就是这三条。

## 1. 默认 TTS 端口：8765 → **8796**

- 8765 是 Python `websockets` 等一大批开发工具示例里的默认端口，撞车概率高。
- 8796 与本仓库另外两个边车挨着（8793 理解层 / 8794 通话 LLM），好认；
  8795 留给 `serve-talk-llm.sh` 提示里的「手动换一个」。
- **LLM 的 8794 不换**：没有撞过，换它只会让已经在跑的人多一次莫名其妙的「没起」。
- Rust 默认值、`scripts/serve-tts.sh`、`services/tts/server.py`、`talk-e2e.sh`、`preview-voices.sh`
  同步改了；新增测试 `rust_and_script_default_ports_agree` 钉住两边一致
  （漂移的症状是「请求一个端口、边车起在另一个」，编译和单测都发现不了）。
- ⚠️ **升级影响**：`config.json` 里 `tts_url` 为空（跟随默认）的用户，升级后会连 8796。
  如果你手工在 8765 上起着一个 TTS 边车，它不会再被用上——关掉它，让守护进程在 8796 上重新拉起即可。
  `tts_url` 显式写了地址的（比如 jason 本机的 8766）**不受影响**。

## 2. 端口被别的程序占了 → 自动换一个空闲端口拉起

- 只对**我们会拉起的**边车生效（有拉起命令、`talk_autostart` 没关）。没有拉起命令时照旧「只报不拉」。
- 选端口：让系统分一个空闲端口（bind `127.0.0.1:0`），通过环境变量交给拉起脚本
  （`AGENTEAR_TTS_PORT` / `AGENTEAR_TALK_LLM_PORT`）。拉起命令里原来写死的同名变量会被替换掉
  （否则内层赋值会赢，边车照样起在被占的端口上）。
- 日志：`TTS 边车：端口 8796 被 python3.11（pid 8918） 占了（…HTTP 404）→ 改用端口 50144 拉起`。
  `config.json` 里**显式写的地址**被占时同样避让，但日志升到 ERROR，写明「本次运行不会用它」。
- **选完端口到边车 bind 之间被抢（TOCTOU）**：边车会立刻退出，此时再换一个端口试一次。
- **不改你的 `config.json`**：换出来的端口是运行期覆盖，外加一份运行态记录
  `<数据目录>/run/talk-sidecars.json`。
  - 为什么要落盘：v0.20.1 起守护进程崩溃后会被自动拉起，而崩溃不走收尾，换端口拉起的边车（2–4 GB）
    会活下来。有这份记录，重启后先把它**接回来**（配置没改 + 在应答 + 听端口的正是记录里的 pid，三条都满足才接），
    不会每崩一次多起一份。
  - `--say` / `--ask` / `--talk-turn` 这些命令行入口也读这份记录，守护进程换了端口它们照样能用上。
  - `--diagnose` 会报「⚠️ 端口被占 → 会自动换」，守护进程已经换好时再报一行「↪ 正在用避让端口：…（✅ 在跑）」。
- 退出（菜单 Quit / SIGTERM）时换端口拉起的和接回来的边车都会被收掉。
- **进程登记按 pid 管理，观测到死亡就摘除**（PR #92 评审后补）：
  - 我们拉起的子进程：观测到退出（`try_wait`）或被我们收掉的**同一刻**，从登记表和信号槽位里一起摘掉；
    每次 `ensure` 开头先扫一遍死掉的子进程。子进程在被回收前 pid 不会被系统复用，
    所以「先摘槽位、再回收」保证 Ctrl+C 的信号不会打到别人。
  - 就绪等待**按 pid** 盯进程，不按名字（同名的旧死进程不会再误伤刚拉起的新进程）。
  - 换端口拉起后等满了没就绪：**杀掉并回收**，不留一个没人知道端口的孤儿。
  - 换出来的端口不再应答：**连同进程一起作废**（我们的子进程杀掉回收；接回来的先重核监听者再发信号）。
  - **接回来的进程不放进信号槽位**：它不是我们的子进程，死后 pid 会被立刻复用，而信号处理函数没法做任何校验。
    代价：Ctrl+C / kill 退出时接回的边车会留下——但运行态记录还在，下次启动会按 pid 重新接回
    （或确认已经不是它了，只删记录）。**泄漏可以自愈，误杀不可逆**，所以选前者。
  - 退出时给接回来的 pid 发信号前，**重核**「在听那个端口的仍是这个 pid」。
  - 运行态记录里的进程还是我们的、但配置改了（或它不应答）：**先收掉它，再删记录**（原来只删记录，那个进程就没人管了）。
  - 拉起命令用了 `env -S`（整串拆分）时**不换端口**并记日志，而不是拼出一条「看上去换了、其实没换」的命令。

## 3. 对话模式这一轮没说出来、原因是边车不可用 → 用 `say` 念一句

- 「语音服务没有启动，这一轮没法回答，请看日志。」（按通话语言：中 / 英 / 泰）
- 用 macOS 自带的 `say`，不依赖任何边车。
- **节流**：同一个原因（哪几个边车不可用）3 分钟内只念一次；原因变了立刻再念；有一轮正常说出来就清零。
- 只在对话模式里念；输入法模式本来就不出声。失败原因不是边车（比如模型回了空）时不念。

## 验证

- `cargo test`：**341 passed / 0 failed / 8 ignored**，脚本默认值集成测试 8 passed。
- **评审后补的调用点变异**（9 处，每处都至少有一条测试变红）：judge 调用点绕过 pid 查询（评审原来发现「不红」的那个）、
  摘除子进程时不清信号槽位、换端口超时不收子进程、就绪等待退回「按名字取第一个」、退出时不重核接回 pid、
  作废覆盖不收进程、reap 什么都不做、配置改了只删记录不收进程、接回的 pid 放进信号槽位。
  这些测试用的是**真进程、真端口、真 lsof**（假边车是一个 `/health` 回 200 的 `http.server`），不只测纯函数。
- **真边车冒烟**（`cargo test -- --ignored smoke_relocate_real_tts`，不起守护进程）：端口被占 → 换到新端口拉起真 TTS →
  合成 153660 字节 → 第二次 ensure 复用、不重复拉起 → 退出时进程、槽位、覆盖、运行态记录全部清干净。
- 变异验证：Relocate 退回 PortTaken、不删旧的端口赋值、节流忽略原因、接回不校验 pid、覆盖不看配置地址——
  **5 处改坏各有测试变红**（「不删旧赋值」在自审重写那个函数后又验了一次，仍然变红）。
- **本机实测**（隔离的数据目录，用 `python3 -m http.server 8796` 占住新默认端口）：
  - `--diagnose` 报出占用者 `python3.11（pid …）` 与「会自动换端口」；
  - 守护进程启动：`端口 8796 被占 → 改用端口 50144 拉起`，10.7s 就绪，运行态记录写入；
  - `--say`、`--ask`、`--talk-turn <wav>` 都走 50144 **出声**；
  - `kill -9` 守护进程 → 边车留下 → 重启后「接回上次换端口拉起的那个（pid 一致）」，没有再起一份；
    再 SIGTERM → 接回的边车也被收掉；
  - 占位还在、边车已收掉时 `--talk-turn` → 这一轮失败 → `say` 念出提示。

## 没测到的 / 已知边界

- **守护进程里真按键双击 → 自动换端口 → 出声**这条没有人手测（请装上后试一次）。
- 被信号杀掉（SIGTERM / Ctrl+C）时运行态记录不会当场删（信号处理里不做文件 I/O），
  下次启动校验 pid 对不上会自动清掉——不影响功能，只是文件会多留一会儿。
- 自己改了拉起命令、端口写死在命令参数里（不读 `AGENTEAR_*_PORT`）的，自动换端口无效，
  会在 90 秒后报「换到端口 … 也没起来」。
- 守护进程启动时第一行「对话模式：… TTS @ …」打的是换端口之前的地址（换端口在后台做），以后面几行为准。
- 仍然没有单实例保护：同时开两个 AgentEar 会各自管自己的边车。

**审查**：Codex 额度到 2026-09-30 才恢复，开 PR 前是 Tier 2 本地对抗自审一轮（修了两处：`env -i` 这类选项下端口赋值插错位置、
运行态记录的 CLI 读取没校验 pid）。PR-Daemon（clestons）四轮评审 **REQUEST_CHANGES**：进程死后从不摘除登记
→ pid 复用误杀 / 槽位被死 pid 占满 / 超时孤儿 / 按名字匹配误伤新进程——已按「pid 为键、观测到死亡即摘除」统一修掉，见上。
