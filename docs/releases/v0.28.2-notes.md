## v0.28.2 — Long recordings are no longer cut off in Qwen3 transcription

**If you use the default SenseVoice recognizer, transcription is unchanged.** The fix applies only when Speech recognition is Qwen3 (0.6B or 1.7B) **and the menu-bar "Qwen3-ASR resident" switch is on**. That switch is off by default.

### What this version does

Until now the resident Qwen3 service stopped decoding after 448 tokens and still reported success. A 281.75-second recording came back with only its first part (about 774 characters). The recording file on disk was complete; the transcript was not.

- The resident Qwen3 service's decode limit is raised from 448 to 6144 tokens, sized for the 15-minute option (upstream uses 4096 for about 15 minutes, with margin on top). Short sentences still stop at the end of speech as before.
- Settings has a new "Recording limit (default 5 min)" row: 5 minutes (default), 10 minutes, or 15 minutes. An invalid value in the config falls back to 5 minutes. The menu-bar timer now counts past 4:15.

### What an upgrade does

The Qwen3 runtime changes from `v0.0.28-agentear.1` to `v0.0.28-agentear.2`. If Qwen3 is already installed, the app downloads the new runtime once in the background (about 99.5 MB, 99,535,412 bytes; the models are not downloaded again). Until it finishes, recognition falls back to the built-in SenseVoice, and switches back to Qwen3 when the runtime is installed. The old runtime folder is not deleted automatically. Users on SenseVoice download nothing.

### Verification

- The new `speech-server` was built from the pinned upstream commit with the patch and published as `speech-runtime-v0.0.28-agentear.2`. The sha256 and byte count in `src/qwen3.rs` were read from that file.
- On 2026-11-10 a real 281.75-second recording was sent to the new `speech-server` (0.6B, runtime unpacked by `--fetch-qwen3`): HTTP 200, 1295 characters, ending with a complete sentence, 37.1 s including model load. The 448-token build returned about 774 characters for the same recording.
- `scripts/lint-shell.sh`, `cargo test`, and `cargo build --release` pass.

### Limits

- The Settings "Recording limit" row and the signed `.app` were not clicked in this pass.
- A 15-minute recording was not decoded, and Qwen3 memory at that length was not measured. The restart-above-4-GiB safeguard is still in place.
- The install-time offline smoke check at the end of `--fetch-qwen3` did not complete in the build environment: the official `speech` CLI under `sandbox-exec` failed there with the old `.1` runtime as well, so it is not caused by this change. It has not been re-run in a normal desktop session.
- The one-shot `speech transcribe` command line has no token-limit option and is unchanged. With the resident switch off, or if the resident service fails and the app falls back to it, Qwen3 transcription still runs through that command line and is not fixed by this release.
- 6144 tokens is a raised limit, not a guarantee for every speaking rate or language.

## 中文

## v0.28.2 —— Qwen3 转写不再把长录音截断

**用默认的 SenseVoice 识别时，转写没有变化。** 修复只在“语音识别”选了 Qwen3（0.6B 或 1.7B），**并且菜单栏“Qwen3-ASR 常驻”开关打开**时生效。这个开关默认是关的。

### 这一版做了什么

之前 Qwen3 常驻服务解码到 448 个 token 就停，HTTP 却仍报成功。一段 281.75 秒的录音只回来前半（约 774 字）。磁盘上的录音文件是完整的，缺的是转写文字。

- Qwen3 常驻服务的解码上限从 448 提到 6144 个 token，按 15 分钟那一档留的（上游给约 15 分钟用 4096，这里在其上留了余量）。短句仍在说完时自然停下。
- 设置里新增“录音上限（默认 5 分钟）”一行：5 分钟（默认）、10 分钟、15 分钟。配置里写了非法值会退回 5 分钟。菜单栏计时不再停在 4:15。

### 升级会发生什么

Qwen3 运行时从 `v0.0.28-agentear.1` 换成 `v0.0.28-agentear.2`。已经装了 Qwen3 的用户，会在后台下载一次新运行时（约 99.5 MB，99,535,412 字节；模型不重下）。下完之前识别先退回内置 SenseVoice，装好后自动切回 Qwen3。旧运行时目录不会自动删除。用 SenseVoice 的用户不下载任何东西。

### 验证

- 新的 `speech-server` 从钉死的上游 commit 加补丁编出，发布为 `speech-runtime-v0.0.28-agentear.2`。`src/qwen3.rs` 里的 sha256 和字节数从这个文件读出。
- 2026-11-10 把一段 281.75 秒的真实录音发给新的 `speech-server`（0.6B，运行时由 `--fetch-qwen3` 解包）：HTTP 200，1295 字，结尾是完整的一句，含模型加载共 37.1 秒。448 的旧二进制对同一段只回约 774 字。
- `scripts/lint-shell.sh`、`cargo test`、`cargo build --release` 通过。

### 边界

- 设置里的“录音上限”一行和签名后的 `.app` 这一轮没有点过。
- 没有解码过 15 分钟的录音，也没有测 Qwen3 在那个长度下的内存。超 4 GiB 就重启的保险还在。
- `--fetch-qwen3` 末尾的断网冒烟在构建环境里没能完成：官方 `speech` 命令行在 `sandbox-exec` 下，连旧的 `.1` 运行时也一样失败，所以不是这次改动造成的。还没有在正常桌面会话里重跑。
- 一次性的 `speech transcribe` 命令行没有 token 上限参数，没改。常驻开关关着，或常驻服务失败退回命令行时，Qwen3 仍走那条命令行，这一版没有修它。
- 6144 个 token 是调高的上限，不保证任何语速、任何语言都能装下。
