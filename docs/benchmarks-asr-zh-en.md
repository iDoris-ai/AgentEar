## 0. 一句话结论

- **英文、中英混合：Qwen3-ASR 1.7B 更好**，配对 bootstrap 区间不跨 0。
- **中文：主口径下没检出差异**。可是结果会随口径变：剔掉「数字写法」这个干扰以后，
  变成 1.7B 更好（§3）。
- **代价是时延和内存**：每按一次键多等约 **2 秒**（冷启动 2.29s 对 0.29s），
  峰值 RSS **2487–2628 MiB（2.4–2.6 GiB）** 对 **268–455 MiB**。1.7B 只能进**高资源档**。
- **0.6B 在三组里都没有显著赢过 SenseVoice**（英文 WER 例外），且每组都比 1.7B 差。

## 3. 中文组的结论取决于口径

中文组「未检出差异」这个结论，是被两处**参考文本的写法**左右的：

1. **数字写法**：FLEURS 参考写 `120 公里`。SenseVoice 输出阿拉伯数字，
   Qwen3 在中文语境里常输出**汉字数字**（实测样例：`一百二十公里`、`八 G`；没有逐条统计比例）。
   60 条里有 16 条含数字，1.7B 的 185 个字错里有 **98 个**出在这 16 条上
   （SenseVoice 是 182 个里的 65 个；这两个数由 `asr-zhen-score.py` 打出，见 `score.md` 末行）。
2. **括号里的外文原名**：参考写「埃德·戴维 (Ed Davey)」，朗读者不念，
   两个引擎也都不转。两边都被记错，但会把差异稀释掉。

| 口径（仅第 1 次运行） | 条数 | SV | 1.7B | 0.6B | 1.7B − SV 的 95% 区间 |
|---|---|---|---|---|---|
| 主口径 | 60 | 7.85% | 7.98% | 9.19% | [−1.24, +1.55] 未检出 |
| 参考去掉括号里的拉丁原文注 | 60 | 3.66% | 3.80% | 5.07% | [−1.31, +1.62] 未检出 |
| 上一条 + 剔除含阿拉伯数字的 16 句 | 44 | 3.98% | **2.06%** | 2.96% | [−3.12, −0.90] **1.7B 更好** |

**怎么读这张表**：

- 剔除数字句是**事后决定的**口径（看了逐句错误之后才加的）。
  它能说明「主口径的平手是被数字写法拉平的」，**但不能当作预先注册的结论**。
- **数字写法不只是评分口径的问题，也是产品差异**：用户在输入法模式下说「120 公里」，
  上屏的是 `一百二十公里` 还是 `120公里`，这是看得见的差别。
  Qwen3 还会在中英之间**插空格**（`我 apply`），SenseVoice 不插。
  哪种更合适是产品判断，**这里不替你选**。
- 「去括号」只处理括号里是纯拉丁文字的情况（11 句），是**启发式的**。
  比如 `(bug)` 可能真被念了。

直接调引擎 CLI，参数和产品一致。每次都起一个新进程（产品就是这么用的），
所以**每一行都包含模型加载**。原始数据在 `data/asr-zh-en-2026-09/perf-raw.tsv`。

| | qwen3-1.7B | 2.285 [2.049, 2.619] | 1.098 | 2487 [2487, 2489] |
| | qwen3-0.6B | 1.962 [1.949, 2.008] | 0.943 | 815 [812, 817] |
| 119.6s（sample02） | sensevoice | 3.102 [3.054, 3.289] | 0.0259 | 419 [418, 421] |
| | qwen3-1.7B | 7.664 [7.657, 7.721] | 0.0641 | 2544 [2540, 2546] |
| | qwen3-0.6B | 5.182 [5.166, 5.202] | 0.0433 | 872 [871, 874] |
| 300s | sensevoice | 7.686 [7.642, 8.790] | 0.0256 | 455 [455, 457] |
| | qwen3-1.7B | 13.158 [13.108, 13.276] | 0.0439 | 2628 [2626, 2628] |
| | qwen3-0.6B | 9.961 [9.813, 10.910] | 0.0332 | 957 [956, 960] |

走产品路径的 180 条（每条一个进程）里，单条墙钟中位数是：SenseVoice **0.17–0.27s**，
1.7B **1.99–2.15s**，0.6B **1.85–1.93s**（按组分开的数据见 `score.md`）。

- **每按一次键固定多出约 2 秒**，来自 speech 进程每次都重新加载模型。
  要消掉这 2 秒，得把 Qwen3 做成**常驻服务**（benchmarks-m3.md §3 已经提过）。
  那样会把约 2.5 GiB 变成**常驻**内存，这笔账这次没测。
- SenseVoice 的 RSS（120s 时 419 MiB）和 M0 记的 419 MB 同数（M0 表没写清单位是 MB 还是 MiB）。
  RTF 则**不可比**：M0 的 0.033 与这里的 0.0259 测法不同（这里是含加载的整进程墙钟）。
  **SenseVoice 的 RSS 随音频变长而上涨**（268→419→455）。
  Qwen3 1.7B 也在涨（2487→2544→2628），**300 秒以上没测**。
- **1.7B 在 300 秒音频上的 RSS 是 2.57 GiB**，比 benchmarks-m3.md 记的
  「1.7B fp16 单条 2.43 GiB」略高。那份是另一个量化档、另一段音频，**两个数不能直接横比**。

## 9. T3.5.6：两档 × 两形态的时延与内存（2026-09-26）

T3.5.6 把 Qwen3-ASR 做成设置窗口里按需下载的可选后端（ADR-0010），提供
**逐次调用**（默认，小内存）与**常驻服务**（菜单栏开关）两种形态。
这一节是高资源档准入第 ③ 条「峰值 RSS 实测入库」的数据，也回答了 §5 留下的
「常驻之后能快多少、要多少常驻内存」。

- 运行时：**AgentEar 自己下载的 speech-swift v0.0.28**（不是 §5 那份 brew 的 0.0.26），
  权重钉在 HF commit、逐文件 sha 校验，speech 跑在断网沙箱里（`src/qwen3.rs`）。
- 走产品路径：`agentear --asr-bench`，同一个进程里用 `config::update` 轮流切换，
  引擎就是守护进程用的 `engine::Dispatch`。每种组合 5 轮：**第 1 轮单列**（冷），
  **第 2–5 轮报中位数 [最小, 最大]**（n=4）。
- ⚠️ **音频是 `say` 合成的**（3.9 s / 16.9 s，16 kHz），**只用来量时延和内存**，
  不比准确率；测的时候 jason 自己的守护进程和 TTS 边车开着（没有隔离）。
  原始数据与复现命令：`data/qwen3-asr-bench-2026-09/`。

| 音频 | 组合 | 第 1 轮 s | 第 2–5 轮 s | 内存 MiB |
|---|---|---|---|---|
| 3.9 s | SenseVoice（对照） | 0.16 | 0.125 [0.122, 0.140] | 275（峰值） |
| | Qwen3 0.6B 逐次 | 1.79 | 1.796 [1.766, 1.810] | 815（峰值） |
| | Qwen3 0.6B **常驻** | 2.21 | **0.093** [0.092, 0.103] | **816**（常驻快照） |
| | Qwen3 1.7B 逐次 | 2.09 | 1.899 [1.879, 1.930] | 2487（峰值） |
| | Qwen3 1.7B **常驻** | 2.04 | **0.190** [0.187, 0.207] | **2491**（常驻快照） |
| 16.9 s | SenseVoice（对照） | 0.57 | 0.385 [0.372, 0.427] | 322（峰值） |
| | Qwen3 0.6B 逐次 | 2.15 | 2.018 [2.003, 2.034] | 816（峰值） |
| | Qwen3 0.6B **常驻** | 2.15 | **0.354** [0.349, 0.367] | **818**（常驻快照） |
| | Qwen3 1.7B 逐次 | 2.43 | 2.482 [2.433, 2.599] | 2492（峰值） |
| | Qwen3 1.7B **常驻** | 2.60 | **0.689** [0.687, 0.690] | **2492**（常驻快照） |

读法：

- **逐次调用每一轮都要付约 1.8–2.5 s**（起进程 + 加载模型），与 §5 的「每按一次键多约 2 s」一致。
- **常驻之后，热态每轮 0.09–0.69 s**：短句上 0.6B 比 SenseVoice 还快，
  长句上 0.6B 与 SenseVoice 持平、1.7B 约慢 0.3 s。**常驻组合的第 1 轮仍要约 2 s**
  （起服务 + 加载模型）——所以产品在切到常驻 / 启动时会在后台先预热一次。
- **常驻的代价**：0.6B 常驻约 **0.8 GiB**、1.7B 约 **2.4 GiB**，这段时间一直占着；
  空闲 10 分钟（`qwen3_idle_secs`）后自动退出，把内存还回去。
- **准入**：两档峰值都在高资源档 ≤4 GiB 内；0.6B（816 MiB）其实也在默认档 ≤2 GiB 内，
  但**不随包**，所以仍是用户显式启用的可选项——默认 ASR 仍是随包的 SenseVoice（Q4）。
- 旁证（**单条合成语音，不是准确率结论**）：同一段音频，0.6B 逐次出「青麦」、
  常驻出「青迈」，1.7B 两种形态都是「清迈」。ADR-0010 RAW §4 也见过 CLI 与 server
  输出不同。**server 路径的准确率没有用 60×3 组重跑过**，常驻形态的准确率目前
  只能说「没有证据表明它更差」，不能说「与 §2 相同」。
