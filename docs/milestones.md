日期：2026-07-29

## 已拍板的三件事

1. **M1 只做到转写**，不含 LLM、不含标签路由、不含语音输出
2. **常驻守护进程用 Rust**（单二进制、无运行时，契合 ASR 的选型理由）
3. **先做丢弃式 Python spike** 跑基准测试，验证通过再写正式代码
4. **ASR 用 SenseVoiceSmall q8**（M0 横比后推翻了 Fun-ASR-Nano，见 `docs/decisions/0001-asr-model-selection.md`）

## M1 · 按键即录即转写

> 「我对着 Mac 说话，快捷键打开开始录音，关闭停止，然后转成文字给我。」

| | |
|---|---|
| 语言 | Rust |
| 形态 | 菜单栏常驻程序（无主窗口） |

```
按下全局快捷键（toggle 开）
  ↓
cpal 采集 16kHz 单声道 PCM
  ↓
再次按下快捷键（toggle 关）
  ↓
raw/audio/<content_hash>  ← 完整提交协议，零丢失
  ↓
llama-funasr-sensevoice 子进程转写（冷启动仅 0.2s）
  ↓
derived/transcripts/
  ↓
文字进剪贴板 + 悬浮窗显示
```

### M1 恰好绕开了两个最难的部分

- **不需要 AEC**：没有 TTS 播放，麦克风不会收到自己的声音。AEC 推迟到 M3。
- **不需要 §3.7 的流式 raw 语义**：快捷键的按下/再按天然给出了段边界，每次录音就是一个有头有尾的文件对象，可以直接用 §3.3 的零丢失提交协议。无边界流推迟到 M3。

**这是选择「M1 只到转写」的额外红利，不要在 M1 里提前引入这两样。**

### macOS 上的两个已知坑

1. **麦克风权限（TCC）**：从终端直接跑的二进制会继承终端的权限，容易产生「我这儿能跑」的假象。M1 必须打成正经的 `.app` bundle，`Info.plist` 里写 `NSMicrophoneUsageDescription`。
2. **全局快捷键**：用 Carbon `RegisterEventHotKey`（Rust 侧走 `global-hotkey` crate）注册**不需要**辅助功能权限；如果改用 `NSEvent` 全局监听则需要，别走错路。

### 验收标准

> ✅ **8/8 全部通过（2026-07-30）。** 实测数据见 `docs/m1-status.md`。
> 之后又补了两块，都在 M1 的范围内（仍然只到转写）：
> **v0.3.0 菜单三语**（English / 中文 / ไทย），
> **v0.3.1 泰语识别**（whisper 引擎 + 模型按需下载，见 ADR-0004 §7）。

- [x] 快捷键 toggle 录音，状态在菜单栏可见（右 Command；`🎙` / `● Ns` / `◌ 转写中`）
- [x] 录音文件按提交协议落进 `raw/audio/`，**杀进程测试**：未提交的临时对象被正确清理
      （单元测试 + 一次真实事故双重验证）
- [x] 转写结果进剪贴板，可直接粘贴，且已过滤特殊 token
- [x] 转写失败时 raw 音频**仍然完好**（实测：把模型文件头部写坏 → 优雅报错不 panic，
      raw 的 sha256 前后一致）
- [x] 常驻内存 ≤ 2 GB（实测空闲 13 MB；bundle 42 MB，多的是 AppKit）
- [x] 按键到开始录音 < 200ms（实测 146 ms）
- [x] `.app` bundle 可分发（`scripts/bundle.sh`）
- [x] 端到端全程 7.8s（录音 7.4s + 提交 28ms + 转写 0.26s）

**不在 M1 范围内**：LLM、标签路由、TTS、录音笔、网络传输、AEC。

## M2 · 理解与路由

转写之后接上标签识别，分流到 `routes/`。这是 README 里「说这是一个 idea / 这是一个任务，自动选分支」的那一段。

**M2 多了一项 M0 发现的职责：技术术语纠错。** 实测 ASR 会把 `raw` 转成 `road`、`knowledge base` 转成 `闹铃是base`，而 jason 的场景全是技术术语。用本地 LLM 结合上下文纠正，比换 ASR 模型划算。

**三项空白已由 [ADR-0002](decisions/0002-m2-understanding-layer.md) 填上：**

| | 决定 |
|---|---|
| 本地 LLM | **Ornith-1.0-9B MLX 6bit**（7.65 GiB），mlx-dspark 提供 HTTP，**常驻** |
| 内存预算 | 从 ≤2 GiB 放宽到 **≤9 GiB**（LLM 常驻 + ASR 子进程尖峰） |
| 标签体系 | 一级封闭集合 8 个（idea/task/note/question/reference/journal/command/unknown）+ 二级自由词表 |
| knowledge base | **独立模块**，双适配器可自由切换（见 [ADR-0003](decisions/0003-knowledge-base-adapters.md)）：个人档 = Markdown + Git；组织档 = Memos（MIT / Go 单二进制）。投递走原生接口，**MCP 用于反向检索** |

**约束**：
- 下游路由只消费 committed 的转写
- `routes/` 是本地权威记录，**先落盘再投递**；MCP 投递失败进重试队列，不阻塞主链路
- 显式标记（用户说「这是一个 idea」）优先于模型推断
- 纠错后必须保留原始转写——纠错是有损操作

## M3 · 实时语音对话（V1 打断式半双工）

> 「App 有个按钮，类似打电话，打通了之后双工可打断地实时交流。」
> —— jason 2026-09-08 口述，完整愿景与架构见 **[ADR-0007](decisions/0007-realtime-voice-architecture.md)**

M3 从「加个 TTS」重新定义为「**做一条可通话的实时链路，并把引擎变成可替换的**」。
**这是 AEC 和流式 raw 语义真正登场的地方**，也是 M1–M2 之外工程量最大的一块。

### V1 / V2 分级（jason 2026-09-08 拍板）

内存门槛做成**产品档位**，不是妥协——低配机器也要能用：

| 档 | 形态 | 内存门槛 | 落在 |
|---|---|---|---|
| **V1** | 打断式半双工（VAD 一检测到开口就掐掉 TTS） | **≤10 GB** | M3 |
| **V2** | 实时全双工（边听边想） | 放宽到 **64 GB** 级 | **未排期**（见下） |

**V2 不占里程碑编号。** 触发条件是「出现经验证覆盖中文和泰语、且在
Apple Silicon 上达到实时的本地全双工模型」，该条件当前不成立。

⚠️ **V1 的措辞纪律**：半双工解决「说完才轮到我」，不解决「一边听一边想」。
**不要描述成「体感接近全双工」。**

⚠️ **`CLAUDE.md` 里「全双工在 2GB 预算内做不到」那句话的理由已改。**
真正的障碍不再是内存，而是**没有「已验证覆盖中泰且达到实时」的候选**
（VoiceChat 11B 仅英文 + 仅研究许可 + aarch64 上 RTF 1.13 达不到实时；
PersonaPlex 7B 未测）。见 ADR-0007 §2.1。

### 子里程碑

| | 内容 | 依赖 |
|---|---|---|
| **M3.0** | **引擎适配层**（按 ADR-0007 §4.2 的能力矩阵，不是「每个都两实现」）+ **§4.4 的编排职责二选一必须在这一步定死** | 无——`src/asr.rs:118` 已经在按语言分派两个后端，这一步是把既成事实显式化 |
| **M3.1** | **TTS 出声**：默认 `say` 保底，可选高质量引擎（Arm 的 T3.3.1） | M3.0 |
| **M3.2** | **通话会话层**：打电话式入口、VAD 打断、AEC、语言随时切 | M3.0、M3.1 |
| **M3.3** | **mock LLM**：查天气 → 语音说出来，证明整条链路通 | M3.2 |
| **M3.4** | **集成接口**：`agentear serve`（OpenAI 兼容）+ MCP + 说明文档 | M3.2 |

**原有的录音输入法形态继续保留**，不被通话形态取代。

### 验收标准

沿用 `docs/asr-selection.md` §4 那张带阈值的表：AEC 自触发率 = 0、
打断响应 < 300ms、误打断 < 1 次/10 分钟、打断后恢复行为一致。

### 选型现状（2026-09-08 实测，见 [benchmarks-m3.md](benchmarks-m3.md)）

`speech-swift` 一个 CLI 里带了 M3 需要的部件：Qwen3-ASR（30 语言 + 22 中文方言
= 共 52 覆盖项，含中英泰 + 语言识别）、VoxCPM2 / IndexTTS2（情感预设）、
Silero VAD、Smart Turn、LocalVQE（AEC **候选，未验收**）、FunctionGemma（工具调用）、
`speech-server` 的 OpenAI 兼容 `/v1/realtime`。
⚠️ **除泰语 ASR 外全部未测**，逐项状态见 benchmarks-m3.md §5 的「本站验证」列。

实测泰语：**纯泰语 CER 0.0%（6/6 逐字全对）**，本样本上优于现有 whisper 链路的 3.1%；
夹英文那一格**两个指标都方向性偏向 whisper**，但样本量不足以量化。
3 轮复跑 22/22 一致。离线 RTF 0.074 —— **实时指标一项未测**。

⚠️ **实测版本 v0.0.26（Homebrew），上游最新 v0.0.27，均为 v0.0.x，API 不保证稳定**
→ 走 CLI/HTTP 边界 + 版本握手 + 契约测试，不链接 SPM 库。锁定与回滚见 benchmarks-m3.md §5.4。

⚠️ **换 ASR 默认引擎仍需 jason 单独拍板。**
2026-09-08 拍板的是**资源分档**（`CLAUDE.md`：默认档 ≤2 GiB / 高资源档 ≤4 GiB），
**不是**「可以换默认引擎」——后者要看中英横比（T3.5.1），那个还没做。
**当前 `speech_swift` 是可选后端，既有用户的默认链路不变。**

⚠️ **资源账**：ADR-0005 的 TTS 1.8 GB + M2 常驻 LLM 7.3 GB ≈ 9.1 GB，
**已贴着 ADR-0002 的 ≤9 GiB 上限**。V1 的 ≤10 GB 门槛要求
**通话时不与 M2 的理解层 LLM 同时常驻**，或改用更小的 LLM。

选型时有一条**约束以前没写下来**（jason 2026-09-02 口述补充）：

> **输出语音要能说方言**：台湾话、广东话、香港话、英语、泰语。
> 允许分阶段——先做普通话或先做英语都行。

这条不是锦上添花，它会淘汰掉一批候选：多数中文 TTS 只做普通话，闽南语和粤语的
可用方案少得多。**把它当筛选条件，与 AEC 可行性同级**，否则很可能选出一个
之后要推翻的方案。

⚠️ **注意方向。** 这里说的是**输出侧**（让它说方言）。输入侧（听懂方言）是另一件事：
现有 SenseVoice 只覆盖 zh/en/yue/ja/ko，**粤语能听、闽南语听不了**。
两侧的方言能力要分别决策，不要混为一谈——见下面「输入侧方言」。

### 输入侧方言：一个已知缺口，尚未立项

`ADR-0001` 选 SenseVoice 时，语种集合是 zh/en/yue/ja/ko。所以：

| 方言 | 听得懂吗 |
|---|---|
| 普通话 / 英语 | ✅ |
| 粤语 | ✅（`yue`） |
| 台湾话（闽南语）/ 吴语 / 四川话 | ❌ |
| 泰语 | ✅ 但走另一条链路（v0.3.1，whisper + Thonburian） |

**如果将来要听懂闽南语**，`Qwen3-ASR` 是目前已知覆盖最广的候选：
官方口径是 **30 种语言 + 22 种中文方言 = 共 52 个覆盖项**（方言含闽南语/吴语/四川话）。
⚠️ 这里原本写成「52 种语言、22 种中国方言」，把 52 和 22 并列了，
**那个读法是错的——22 是含在 52 里面的**。三份文档统一用上面这句。

它在 M0 横比里**指标最好但因为「需要 Python + MLX 运行时」而出局**（ADR-0001）。

⚠️ **那条排除理由在 M2 之后会变弱，但不等于自动失效**：ADR-0002 把措辞修订成
「Rust 守护进程自身不内嵌 Python 运行时；外部推理服务的实现语言不受限，
但必须是独立进程 + 明确协议边界」，而 M2 本来就要常驻一个 mlx-dspark 边车——
那时再挂一个 MLX 上的 ASR，边际成本比当初评估时低得多。

**资源那一关已经通过**：`CLAUDE.md` 2026-09-08 改成了 ASR 分档
（默认档 ≤2 GiB / 高资源档 ≤4 GiB），MLX 上的 ASR 可以走高资源档。
**但立项前提仍是「真的需要闽南语」**——在那之前这只是一个记录在案的缺口。

## 依赖关系

```
M0 基准验证 ──→ M1 按键转写 ──→ M2 理解路由 ──→ M3 语音输出
                                                    │
M3.5 录音笔刻画（到手即做，不阻塞主线）──→ M4 接入 ──→ M5 硬件
```

**M0 是唯一的硬门槛**，其余里程碑之间可以按兴趣调整顺序，但 M3.5 必须在 M4 之前。
