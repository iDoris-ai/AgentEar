# 计划：菜单国际化 + 泰语支持

状态：**待评审**（2026-08-22 拟）
前置：v0.2.3 已修掉「非中文转写被当日志丢弃」的 bug。

本文覆盖两件独立的事，容易被混为一谈，先划清：

| | 说的是什么 | 由谁决定 |
|---|---|---|
| **界面语言** | 菜单栏那些字显示成中文还是英文还是泰文 | 用户在菜单里选，默认 **English** |
| **识别语言** | 用哪个 ASR 引擎、按什么语言解码音频 | 中/英/日/韩自动检测；**泰语必须显式选** |

两者互不影响：界面切成泰文不改变识别行为，识别切成泰语也不改变菜单文字。

---

## 0. 已实测确认的事实（计划的依据）

1. **SenseVoice 覆盖中、英、粤、日、韩**，中英混合的中文部分没问题。
   英文实测完全正确（v0.2.3 修复后）。
2. **中英混合里的英文技术术语必错**。Docker → `doocca`、Kubernetes →
   `cuubber needs`、raw → row/road/ro/roll。这是 M2 术语纠错的职责，
   换 ASR 模型解决不了，本计划不碰。
3. **泰语不可用，且语种标记不可信**。两次实测：

   | 样本 | SenseVoice 输出的标记 | 正文 |
   |---|---|---|
   | jason 录的泰语 | `<\|en\|>` | `Satly cr 봄金冷兔 or passa tie` |
   | `say -v Kanya` 合成 | `<\|yue\|>` | `s what Lee cr 봄 gar榔토up赣lu 점심 pass sat tie。` |

   同一语言两次给出两个不同的错误标记。**结论：不能按语种标记自动路由到
   泰语引擎。** 这是本计划最重要的一条约束——它排除了「全自动、零设置」
   的方案。
4. **whisper.cpp 在工作区里但没构建过**：`/Users/jason/Dev/tools/whisper.cpp`，
   HEAD `7de8dd78`，无 `build/bin`，`models/` 下只有 `for-tests-*` 的
   几百 KB 桩文件，**没有任何可用的真实模型**。
5. **macOS 自带泰语 TTS 嗓音 `Kanya`**，可用于冒烟测试。
   **但它不能用来算 CER**（见 §3 的风险）。

## 1. 阶段 A：菜单国际化（界面语言）

### 现状

`src/tray.rs` 里所有菜单文案都是硬编码中文字面量，约 20 处。

### 要做的

1. 抽一个 `src/i18n.rs`：

   ```rust
   pub enum Lang { En, Zh, Th }   // 默认 En

   /// 按当前界面语言取文案。key 是稳定标识，不是英文原文——
   /// 免得改英文措辞时把另外两种语言的映射也打断。
   pub fn t(key: Key) -> &'static str;
   ```

   用 `enum Key` 而不是字符串 key：漏翻一条是**编译错误**，不是运行时
   显示成 key 本身。三语的表放在同一个 `match` 里，横向对照着写。

2. `Config` 加 `ui_lang: Lang`，**默认 `Lang::En`**。
   `#[serde(default)]` 已经在 struct 上，老配置文件不会报错。

3. 菜单加「Language」子菜单：`English` / `中文` / `ไทย`，带勾选态。

4. 切换**立即生效不重启**：菜单每次展开都走 `menuNeedsUpdate:` 重建
   （`tray.rs` 已经是这个结构），改完 config 下次展开就是新语言。
   菜单栏标题由 0.5s 定时器刷新，也会自动跟上。

### 需要注意的

- **状态标题里的「转写中」也要翻译**（`tray.rs::title()`），别只翻菜单。
- **动态拼接的文案**（`■ 停止录音（已录 12s）`、`系统默认（设备名）`）
  不能简单查表，要留占位符。
- 日志文案**不翻译**，保持中文。日志是给 jason 和我看的，不是给终端用户的。

### 验收

- 默认全新配置启动 → 菜单是英文
- 切中文 → 立刻中文；重启后仍是中文
- 切泰文 → 菜单是泰文，**且不影响识别行为**
- 老的 `config.json`（没有 `ui_lang` 字段）能正常加载，语言取默认 En

## 2. 阶段 B：识别语言的选择方式

### 为什么不能全自动（这条最容易被想当然）

§0.3 已实测：泰语的语种标记在 `en` 和 `yue` 之间乱跳。所以
**「先用 SenseVoice 跑一遍，发现是泰语就改用 whisper」这个方案不成立**
——SenseVoice 从不认为那是泰语。

### 方案

菜单加「Recognition / 识别语言」子菜单，两项：

```
Recognition ▸
  ✓ Auto (Chinese / English / Japanese / Korean)   ← 默认，走 SenseVoice
    ไทย Thai                                        ← 走 whisper，需先下载模型
```

只有两项，因为**真实的分叉只有一个**：用 SenseVoice 还是用 whisper。
中英日韩在 SenseVoice 里是同一份权重、同一次推理，再列出来只是假选项。

`Config` 加 `asr_lang: AsrLang { Auto, Thai }`，默认 `Auto`。

### 快捷键要不要

**先不加。** 理由：jason 本人日常不说泰语，切换是低频操作（给泰国同学演示
时才用），菜单够了。真出现「一场对话里中泰来回切」的需求再加，那时才知道
该绑什么键。现在加等于凭空猜一个绑定。

## 3. 阶段 C：泰语引擎选型（ADR-0004）

### 候选

**whisper.cpp**。理由：支持泰语、单二进制无运行时（符合项目「不背 Python
运行时」的约束）、仓库已经在工作区里。

`CLAUDE.md` 写了「Whisper 不做主链路」——那条针对的是中文 CER，
**主链路仍然是 SenseVoice**，用 whisper 跑泰语不违背它。

### 要测什么（沿用 M0 的口径，便于横比）

| 指标 | 为什么要 |
|---|---|
| 泰语 CER | 能不能用的唯一判据 |
| 模型体积 | 决定下载体验，`medium` ≈ 1.5 GB / `large-v3` ≈ 3 GB |
| 冷启动 | 决定要不要常驻。SenseVoice 是 0.2s 所以不用常驻，whisper 未必 |
| RSS 峰值 | M1 预算 ≤2 GiB，**large-v3 很可能直接超预算** |
| RTF | 能不能接受 |

至少测 `small` / `medium` / `large-v3` 三档，找到「够用的最小档」。

### ⚠️ 风险：没有泰语真实语料，CER 算不出来

这是本计划最大的窟窿，得先说清楚：

- `say -v Kanya` 合成的音频**不能用来算 CER**。TTS 没有口音、没有语速
  变化、没有口头语、没有环境噪声，跑出来的数字会**显著优于真实表现**，
  拿它做选型会选错档位（很可能误判 `small` 够用）。
- 它只能用来做**冒烟测试**：验证「whisper 确实吐泰文而不是乱码」、
  验证进程调用链通了。这个价值是有的，但仅此而已。

**所以选型分两步：**

- **C1（现在能做）**：构建 whisper.cpp、下载模型、用合成音频冒烟，
  测体积 / 冷启动 / RSS / RTF——**这四项与语料真实性无关，现在测就是准的**。
- **C2（需要 jason 提供）**：**找泰国同学录 5–10 段真实泰语**，
  每段 10–30 秒，附文字稿。有了它才能算 CER，才能定档位，ADR-0004 才能拍板。

在 C2 的语料到位之前，**ADR-0004 只写到「候选与非 CER 指标」，不下最终结论**。
不要用合成语料的数字冒充实测结论——M0 的教训就是「单样本得出的准确率结论
不可靠」，这里连样本都是合成的。

## 4. 阶段 D：模型按需下载

jason 2026-08-22 拍板走**方案 A**：主包保持 241 MB，第一次切到泰语时再下载。

### 要做的

- 用户在菜单里选 `ไทย Thai` → 若模型不存在，提示并开始下载
- 下载到 `vendor/models/`（`AGENTEAR_VENDOR` 可覆盖）
- **必须校验 SHA-256**，否则下坏的模型会以「加载失败」的形式暴露，
  很难查
- **下载中途失败/退出要能恢复**：先下到 `.part`,校验通过再 rename。
  与 `store.rs` 的提交协议同一个思路——**不完整的文件绝不能出现在最终路径上**
- 菜单显示进度；下载期间 `ไทย` 项置灰
- 下载失败要退回 `Auto` 而不是卡在一个不可用的泰语档

### 从哪下

Hugging Face 的 `ggerganov/whisper.cpp` 仓库有官方 GGML 权重。
**这是一次性的、用户显式触发的下载，不违背「录音和转写不经过第三方服务器」**
——那条约束针对的是音频数据外流，不是取模型。这一点要在 README 里写明白，
免得日后被当成违反隐私承诺。
