# 验收 — 用户视角「算不算做好了」

判据一律从 jason 实际使用的角度写，不写内部指标。每条都配一个**能跑的验证方式**。

---

## A1 术语纠错不再改错项目自己的词

**场景**：口述一段包含项目术语的话（raw / derived / routes / committed / provisional /
SenseVoice / whisper / vendor），开着术语纠错上屏。

**算做好了**：
- 这些词一个都不被「纠正」成别的东西。特别是 `ro的目录` / `road目录` 要还原成
  **raw**，不是 repo。
- 术语表之外的普通话内容不被改写（不润色、不把口语改成书面语）。
- 我能自己往术语表里加词，不用改代码、不用重新编译。

**怎么验**：`cargo test correct` 里的长文回归用例（用真实录音的转写文本，
断言 raw 出现、repo 不出现）；以及手动跑
`./target/release/agentear --transcribe spike/audio/sample02.wav`。

## A2 说完一句话，系统知道这是什么

**场景**：口述「这是一个 idea，给录音笔加个 WiFi 模块」或「帮我查一下明天的日程」。

**算做好了**：
- 转写完之后，系统给出一个标签（idea / task / note / question / reference /
  journal / command / unknown），并落进 `routes/`。
- **我明确说了「这是一个 idea」时，一定按 idea 走**——不能被模型的推断覆盖。
- 判错的时候我能看出它判成了什么（日志或文件里看得到），不是黑箱。
- 标签基准从 6/8 提高到 **至少 7/8**，且两条原本判错的用例有明确定义可查。

**怎么验**：`spike/m2_bench.py` 的标签部分（扩充后的用例集）跑出 ≥7/8；
`routes/` 下出现对应的文件。

## A3 我知道 M3 能不能做方言

**场景**：我问「台湾话和粤语的语音输出到底能不能本地做」。

**算做好了**：
- 有一份文档回答这个问题，**结论是「能」或「不能」，不是「待调研」**。
- 每个候选都写清楚：能不能本地跑、许可能不能随 app 分发、模型多大、
  质量大概什么水平、有没有实际跑通的证据。
- 如果结论是「不能」，明确写出 M3 因此要怎么改（只做普通话 / 推迟 / 其他）。
- **这一步不替我拍板选哪个**——给我事实和建议，选型是我的事。

**怎么验**：`docs/decisions/0005-tts-selection.md` 存在，且里面每个候选都有
「本地可跑」「许可」「实测证据」三栏，没有空白。

## 全局不可退让（任何一条被打破都算没做好）

1. **隐私**：录音、转写、标签识别、TTS 全部本地。任何候选方案只要需要把
   音频或文字发到第三方服务器，直接出局，不进候选表。
2. **主链路不能被拖垮**：术语纠错、标签识别、路由投递中的任何一环失败，
   都不能让文字上不了屏。降级要静默且可见于日志。
3. **原始数据不可损**：`raw/audio/` 是丢了不可重建的那一份。纠错、标签、路由
   都是可重算的下游，任何一步都不许改动或依赖 raw 的成功写入之外的东西。
4. **不许自动删用户数据**：`routes/` 与 transcripts 只增不删。
