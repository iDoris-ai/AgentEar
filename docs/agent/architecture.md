# 技术骨架与不可破的边界

只写**约束**和**契约**，不写实现细节。违反这里任何一条的实现，评审必须打回。

---

## 分层与数据流

```
麦克风 → raw/audio/          原始字节，ASR 之前落盘并 fsync，丢了不可重建
           ↓ ASR（SenseVoice 子进程 / whisper 子进程）
       derived/transcripts/  模型输出，可从 raw 重算
           ↓ 术语纠错（LLM 边车，可选，失败退回原文）
       derived/transcripts/  纠正后覆盖，纠正前另存一份 .raw 后缀
           ↓ 标签识别（LLM 边车）
       routes/               下游决策，可重算
```

**每一层只依赖上一层的产物，不许跨层。** 标签识别读转写文本，不读音频；
路由读标签，不重新问模型。

## 不可破的边界

### B1 raw 优先，且不依赖任何下游成功

原始音频必须在 ASR 之前落盘。转写失败、纠错失败、标签识别失败、进程 OOM，
都不能毁掉那一份忠实记录。这是 README「先存后分流」的执行点。

### B2 LLM 边车是独立进程，不是库

Rust 守护进程**自身不内嵌 Python 运行时**。外部推理服务实现语言不受限，
但必须是独立进程 + 明确协议边界（可独立重启、独立崩溃）。这是 ADR-0002 的措辞，
mlx-dspark 就是按这条划的线。

推论：**边车挂了，主链路必须还能用**。所有对边车的调用都是尽力而为——
接口返回「有结果」或「没有」，不返回错误让调用方处理。

### B3 对端身份必须校验

连边车之前确认对面确实是我们的模型服务（响应里含 `mlx-dspark` 标识）。
2026-09-02 实测踩过：端口 8791 被本机另一个项目占着，不校验就会把
**别人服务的业务回答**当成纠错结果粘进用户正在打字的窗口。

### B4 有损操作必须留下原件

术语纠错和标签识别都是模型的判断，都可能错。任何覆盖式写入之前，
先把被覆盖的那一版存下来。判断「是 ASR 错了还是 LLM 改坏了」只能靠这个。

### B5 显式优先于推断

用户在语音里明说「这是一个 idea」，就按 idea 走，**模型的推断不得覆盖它**。
这是 README 定的产品行为，不是可选优化。

### B6 routes 是本地权威记录，先落盘再投递

投递到知识库（ADR-0003 的双适配器）失败进重试队列，不阻塞主链路，
也不影响 `routes/` 里已经落好的那份记录。

## 与外部服务的契约

| 依赖 | 形态 | 挂了会怎样 |
|---|---|---|
| `llama-funasr-sensevoice` | 每次录音起一个子进程（冷启动 0.2s） | 转写失败，raw 完好，报错不 panic |
| `whisper-cli` | 泰语路径，同上 | 泰语不可用，主链路不受影响 |
| `mlx-dspark` 边车 | 常驻 HTTP，默认 127.0.0.1:8793 | 纠错与标签降级，文字照常上屏 |

**内存预算**：M1 阶段 ASR 侧 ≤2 GiB 不变；M2 起因常驻 LLM 放宽到 ≤9 GiB
（实测 LLM 常驻 7.32 GiB + ASR 尖峰）。**放宽只针对 LLM 这一项。**

## 明确不做（这几件在本轮范围外）

- 不做 TTS 实现，不做 AEC，不做打断（M3，本轮只做 TTS 可行性调研）
- 不引入新的 ASR 引擎，不为闽南语听力改动 ASR 选型（需 jason 单独拍板）
- 不做录音笔接入（M3.5/M4，机器未到手）
- 不做知识库的实际投递实现（ADR-0003 的适配器，排在 routes 落盘之后）
