# 一级标签：定义、判别依据与评测集

前置：`docs/agent/spec.md` §2（数据结构）· ADR-0002 §3（标签体系的由来）

本文只做一件事：**把 8 个一级标签的边界定义到「人看了不会犹豫」的程度**，
并给出评测集。定义不清就开工，等于把 M0 那 6/8 固化下来。

---

## 1. 为什么要重新定义

M0 的 M2 基准里标签分类只有 **6/8**，两条判错：

| 用例 | 期望 | 模型给的 |
|---|---|---|
| 今天开会讨论了接入层的传输协议 | note | journal |
| 帮我查一下明天的日程 | command | task |

**这两条不是模型能力问题。** 当时的提示词是一行「把下面这句话归入其中一类：
idea / task / note / …，只输出类名」——**没有给任何定义，没有例子**。
模型只能按标签名的字面意思猜，而「开会讨论了什么」既像随手记也像当天流水，
「帮我查日程」既是指令也是一件待办。**人看了都会犹豫的边界，不能指望模型稳定。**

所以这个 task 的第一步不是写代码，是把边界写清楚。

## 2. 八个标签

每条都给**一句话定义**和**一个判别问题**——判别问题是用来当场做决定的，
比定义更实用。

| 标签 | 定义 | 判别问题 |
|---|---|---|
| `idea` | 一个还没决定要不要做的想法 | 「他承诺要做了吗？」没有 → idea |
| `task` | 一件确定要做的事，有交付物 | 「要我**记下来以后做**吗？」是 → task |
| `command` | 要系统**现在**执行的指令 | 「他在等系统**立刻**给反应吗？」是 → command |
| `note` | 一条知识、事实、结论 | 「一年后单独拿出来看，还成立吗？」成立 → note |
| `journal` | 当天发生了什么、当时的状态 | 「离开『今天』这个语境还有意义吗？」没有 → journal |
| `question` | 一个待解答的疑问 | 「这句话的目的是**求一个答案**吗？」是 → question |
| `reference` | 指向外部资源的指针 | 「主体是**链接或出处**吗？」是 → reference |
| `unknown` | 无法归类，或内容无意义 | 以上都不像 → unknown。**宁可 unknown 不要瞎猜** |

### 2.1 两组最容易混的，单独说清楚

**`note` vs `journal`：看它离不离得开「今天」。**

- 「SenseVoice 的冷启动只要 0.2 秒」→ **note**。这是个事实，一年后仍然成立。
- 「今天开会讨论了接入层的传输协议」→ **journal**。它记的是「今天发生了这件事」，
  离开时间语境就没有信息量了（讨论出什么结论才是 note）。

⚠️ **这一条是产品决策，待 jason 确认（progress.md 的 Q1）。**
按上面的判别问题，M0 那条用例应该归 **journal**，也就是说
**M0 的「期望 note」本身可能就是错的**——模型当时答 journal 反而对。
这不是我能单方面拍板的事，所以：实现按本文档做，但**这条用例在评测集里
标了 `⚠️Q1`，如果 jason 认为该归 note，改的是定义不是模型**。

**`command` vs `task`：看他等不等系统立刻反应。**

- 「帮我查一下明天的日程」→ **command**。他在等一个回答。
- 「记得给术语表加上 Kubernetes」→ **task**。这是让系统**记下来**，不是现在做。

判别问题里的「立刻」是要害：两者都是祈使句，区别只在**期待的响应时间**。

## 4. 实测结果（2026-09-02）

`~/.agentear/llm/venv/bin/python spike/m2_bench.py --url http://127.0.0.1:8793`

| 阶段 | 用例数 | 命中 |
|---|---|---|
| M0 基准（提示词只有一行「归入其中一类」，无定义） | 8 | **6/8 = 75%** |
| 本次，加入定义后第一轮 | 18 | 13/18 = 72% |
| 本次，定义补完后 | 18 | **18/18 = 100%** |

按类：command 2/2、idea 3/3、journal 2/2、note 2/2、question 3/3、
reference 2/2、task 2/2、unknown 2/2。

### ⚠️ 生产代码路径是 17/18，不是 18/18

上面那张表是 `spike/m2_bench.py` 跑的，而**它和产品用的不是同一个解析器**：
基准把输出里所有非 `[a-z]` 的字符删掉再匹配（于是「我觉得应该是 note 吧」
会变成 `note`），产品要求**整体相等**，那种输出一律 `unknown`。
两套结果因此会分叉——codex 评审指出了这一点。

**以生产路径为准**（`cargo test --release -- --ignored`，走 `src/label.rs`）：

```
生产路径实测：17/18
  "要是能用语音直接建任务就好了" 期望 idea 得到 task
```

判错的那条很有意思：句子里有「建任务」三个字，模型被字面带走了，
而按定义「他承诺要做了吗？」——「要是……就好了」显然没有承诺。
**这是模型能力问题，不是定义问题**（定义已经说清楚了），
所以它留到 T2.2.2 的 few-shot 里解决，不再改定义。

**M0 判错的那两条现在都对了**，而且是在用例数翻倍、难度提高（加了贴边界的用例）
的前提下。这证实了立项判断：**那两处失败是定义问题，不是模型能力问题。**

### 中间那轮 72% 教了两件事

第一轮加定义只到 13/18，五条判错。分析后发现两类原因：

1. **两条是我自己的期望值有问题**，不是模型错：
   - 「现在几点了」我归成 command，但按我自己写的判别问题「目的是求一个答案吗」，
     它应该是 **question**。改了期望值——**改的是我应用定义时的错误，不是迁就模型**。
   - 「ADR-0004 里记了泰语选型的全部局限」在 reference 和 note 之间确实模糊。
2. **三条是定义没覆盖到的情况**：
   - question 类 1/3 最差，而两条判错的共同点是**没有问号**（有问号那条就对了）。
     模型在靠标点判断。定义里补上「口语里疑问句常常没有问号，不要靠标点判断」后全对。
   - 「啊对对对」被判成 idea。定义里补上「语气词、口头禅、附和一律 unknown」后对了。

## 5. 这个评测集的局限（先说清楚，免得数字被过度解读）

⚠️ **最重要的一条：100% 是在「我自己写的、并且我迭代了三轮定义去适配的」
18 条用例上得到的。** 这更接近训练集上的分数，不是泛化能力的证据。
定义每改一次都是在这个集合上调优，过拟合的风险是实打实的。

1. **18 条全部是我写的**，不是从 jason 的真实录音里采的。真实口语有大量
   「呃」「那个」「不拉不拉」，句子边界也不清楚——评测集里的句子太干净了。
   `spike/audio/sample02.wav` 的转写就是活生生的反例：一整段话里混着
   idea、note、command 好几种意图，根本不是「一句话一个标签」。
   **真实场景可能需要先分句，而这个评测集完全没覆盖那一步。**
2. **每类只有 2–3 条**，任何一条判错都让该类的准确率掉 33–50%。
   这个规模只够看「定义有没有帮上忙」，**不足以给出稳定的准确率排名**。
3. **第 9 条的期望值本身待确认**（Q1）。在 jason 拍板之前，
   涉及它的分数应当报两个版本。
