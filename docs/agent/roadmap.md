## 已完成（不在本轮范围）

- **M0 ASR 基准验证** — 四模型横比，选定 SenseVoiceSmall q8（ADR-0001）
- **M1 按键即录即转写** — 验收 8/8，v0.3.1 已发布。含三语界面与泰语识别

## M2 — 理解与路由

目标：转写之后接上理解层。让文字**准确**（术语不被识别错），并且**知道自己是什么**
（idea / task / note …），据此分流到 `routes/`。

- **F2.1 项目术语表** — 修 M2a 暴露的长上下文误纠：给模型一份本项目固定词汇清单，
  而不是让它每次从上下文猜。这是唯一一块**已有失败证据**的工作。
- **F2.2 标签识别与路由** — 先重新定义 8 类边界（M0 基准 6/8 的两处失败是定义问题，
  不是模型能力问题），再实现识别与 `routes/` 落盘。显式标记优先于模型推断。

不在 M2 本轮：知识库的实际投递（ADR-0003 的双适配器）。`routes/` 先落盘，
投递排在其后。

## M3 — 语音输出与打断

目标：让 agent 能说话，并且能被打断。**本轮只做可行性摸底，不做实现。**

- **F3.1 TTS 方言可行性** — 只回答一个问题：台湾话/闽南语、粤语的本地 TTS
  到底有没有可用方案。结论可能推翻 M3 的整体设计，属于「高风险未知项前置」，
  与 M3.5（录音笔刻画）同一性质。

不在本轮：TTS 实现、AEC、打断式半双工。那三样要等 F3.1 有结论。

## 后续（本轮之后，顺序未定）

- **M3.5 录音笔能力刻画** — 机器到手即做，不排队
- **M4 录音笔接入** — 依赖 M3.5 的结论
- **输入侧方言** — 闽南语听力缺口。要动就得推翻「ASR 侧仍按原标准」那条约束，
  需 jason 单独拍板，**不在本轮**
